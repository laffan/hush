# Hush

A minimal, distraction-free writing app for macOS. Hush lives in your menu bar and gives you a clean space to write — no window chrome, no clutter, just text.

## Features

**Editor** — A Markdown editor with inline syntax highlighting (headings, bold, italic, links, code), adjustable column width, and 16 color themes across light, dark, and sepia appearances. Heading `#` markers stay hidden unless your cursor is inside the heading being edited.

**Styles** — Combine theme, font, font size and line height into specific "styles" that you can easily create and move between via the command palette — every saved style gets its own `Use Style: <name>` entry, and an `Edit Styles` entry opens a three-column modal (style list on the left, settings in the middle, live preview on the right) for managing them. Clicking a style in the left rail both selects it for editing and applies it to the editor. Each style optionally overrides bg / fg / **links** / cursor / selection / **header** colour, and can mark headers as **underlined**, suppress their colour, or normalise their size. The **Links** override colours rendered markdown links and `[[wikilinks]]` in both docs and notebook text shapes; it defaults to the text colour (so links read as plain underlined text until you pick a colour). The edit modal previews every change live, including the header overrides — flipping the toggle paints the matching `==FLAG==` callouts and `#` headings in the active editor and any open panes. Inside the modal, hovering theme or font dropdown options previews them on the right-hand pane and snaps back when the dropdown closes. The Colors section's **Light** and **Dark** appearance tabs each list *every* theme in their Theme dropdown (not just the ones whose natural appearance matches the tab), grouped under **Light** and **Dark** section headers, so you can pair any theme with either appearance. Selecting a style also repaints the app's interface chrome (sidebar text, buttons, command palette) to match the style/theme's text colour rather than a generic light/dark grey, and an explicit cursor-colour override keeps working with **Block** or **Underline** cursor modes (the caret picks up the override instead of falling back to the heading colour). The fg / header / links overrides reach the notebook canvas too — text shapes and toolbar icons follow the text colour, markdown headings the header colour, and links the link colour; the background-colour override also paints the notebook shelf, toolbar, and floating popups, and Private Mode's hide-boxes track the foreground override rather than a flat black/white. A **Background Image** block adds optional decorative imagery: tick Enable, pick an image (stored inline as a data-URL so it rides sync and export), then dial in display (fit / contain / stretch / original), repeat (none / tile / tile-x / tile-y), blend mode (composited with the background colour), and opacity. The image renders behind the editor text in Docs and beneath the dot/line grid on notebook canvases. The **Cursor** picker selects between **System** (the default thin caret), **Block** (block-width filled caret), and **Underline** (block-width 3 px strip below the baseline) — replaces the older Block Cursor checkbox. A **Line Indicator** picker just below it adds a focus-following "highlight the current line" affordance: **None** (default), **Left Arrow** (cursor-coloured triangle 10 px outside the text column, pointing inward), **Double Arrow** (the same triangle on both sides of the column), **Left Border** (3 px stripe 10 px to the left of the text), **Border** (3 px stripes 10 px outside each side), or **Highlight** (subtle wash behind the line). The indicator paints per *visual* line (soft-wrapped paragraphs land on the right wrapped row, not centred across the paragraph) and only on the editor that currently holds focus — a stack with three open docs paints the indicator on the one you're typing in, not on all of them. Its colour is a regular **Line Indicator Color** swatch in the Colors section (light + dark each get their own value); leaving it unset falls back to the style's cursor colour. Styles support **JSON import / export**: an **Import styles…** button under the style list ingests a single style, an array, or a `{ styles: [] }` payload (each lands as a fresh style, auto-suffixed on name collision), and an **Export style as JSON** button at the bottom of the settings column downloads the current style — background image included. Bundled **preset styles** in `src/assets/style-presets/` are auto-seeded into the user's styles list on first launch — drop new `.json` files into that folder and they appear as normal styles in the rail. Each preset is tracked by filename in `seededPresetFiles` so deleting one keeps it gone, and a new preset added in a later build still lands on the existing install.

**Post Processing** — Optional per-style overlay of decorative effects: scanlines, vignette, neon glow on text, soft drifting bloom. Off by default; users with no style configured pay nothing (no DOM, no canvas, no listeners — the entire shader runtime is dynamically imported only when a style with an enabled effect is applied). The Post Processing block in the style edit modal carries an Enable toggle, a layer dropdown (hover to preview each option live in the preview pane), a master intensity slider, and a per-layer set of knobs. Three layers ship: **Vignette + Scanlines** (CSS, static, free idle), **Phosphor Scanlines** (CSS — scanlines plus a `text-shadow` phosphor glow that reaches actual editor text via an injected stylesheet, scoped per-style), and **Neon Bloom** (WebGL2 — three soft colored glow blobs drifting slowly across the screen, screen-blended). Each layer's knobs include opacities, colors, and effect-specific settings. Animated layers pause their `requestAnimationFrame` loop while the page is hidden or the window is unfocused, so the GPU/CPU goes quiet when you tab away. A safety hook (`window.__hushShaderPanicCleanup()`) tears down every artifact (host element, injected stylesheets, scope classes, custom properties) regardless of internal state.

**Ratchet Mode** — Forward-only writing. Pick a duration (5–30 minutes) and the editor locks out deletion, selection, and all navigation. The current line is pinned to the center of the screen with previous lines scrolling up above it (typewriter-style). The cursor is always at the end of the document. The timer persists across app restarts.

**Private Mode** — Replaces all characters with opaque boxes so you can write without anyone reading over your shoulder. The boxes follow the active style's text-colour override (falling back to black/white by background luminance). Toggle with `⌘⇧P`.

**Word Count** — Optional live word count pinned to the top of the text column, horizontally centered just below where the Ratchet timer appears. When Ratchet mode is also active, the count stacks directly beneath the timer in the same pill style. Counts are labelled inline so the pill stays self-explanatory: `42 words` in a regular doc, `12 section / 87 total` in a project (the doc the cursor is currently inside, then the whole project, updated as the cursor crosses separator lines). Selecting text appends a selection slot automatically — `3,000 words / 1,500 selected` outside a project, `12 section / 87 total / 1,500 selected` inside one. The pill stays click-through so editor drag-selects aren't intercepted. Doc-mode floating panes carry their own word count next to the title (independent count per pane). Counting strips `%%…%%` comments, image markdown, and any text past the `---%` end-of-document gray-out marker so editorial notes don't inflate the total. Toggle with `⌘⇧W`.

**Typewriter Mode** — Locks the cursor to a fixed line on screen. Drag the boundary to reposition it. The document scrolls to keep the cursor in place. Doc-only — the shortcut and command palette entry are suppressed while a notebook is the active editor. Floating doc panes and stack columns each carry their own scoped typewriter line (centred vertically, clipped to the pane/column boundary) so the mode can be toggled independently per editor surface.

**Zen Focus** — Fullscreen distraction-free writing space. Toggles with `⌘⇧S` (configurable). Available in Docs, doc panes, stack columns, and notebook text shapes — picks whichever surface you're currently editing, mounts it inside a fullscreen overlay at a larger font size (Settings > Editor > Zen Focus), centres the active line vertically, fades the top and bottom thirds of the window with gradient curtains, and dims surrounding sentences via the existing focus-mode opacity setting (focus mode auto-engages on entry and restores its prior state on exit). A **Window** control (1 / 3 / 5 / 7) loosens the typewriter lock so the cursor can drift one, two, or three lines either side of the centre line before the document scrolls — `1` keeps the pure typewriter behaviour where the cursor stays pinned to the centre. The Window picker surfaces twice: as a dropdown in Settings > Editor > Zen Focus, and as a chip group in the bottom-of-window quick-settings pill (a small `^` caret fades in whenever the cursor enters the bottom 200 px band; hovering reveals the Dim / Font / Window controls). The pill itself renders in the app's UI font so it reads as chrome rather than picking up the editor style. A shortcut hint pill in the corner fades in on mouse motion. Esc or the toggle shortcut exits; the edits flow back to the source on close.

**Selection Focus** — Selection-aware companion to the regular Focus shortcut (`⌘S`). With an empty selection the shortcut toggles per-context Focus mode as before; with a non-empty selection in the active editor surface (main, doc pane, or stack column) it instead drops the user into a fullscreen overlay that shows only the selected text — centred vertically and horizontally, painted in the theme background so every other piece of chrome disappears, the column width matched to the source view's width so the line measure carries over, type at the source's own font-size bumped 20 % by default (live-tunable via a Font slider mounted in the same bottom-of-window pill Zen uses). The overlay mounts a real CodeMirror seeded with the captured selection so every cursor type, formatting shortcut, and base-extension plugin behaves identically to the source. The same shortcut (or Esc) exits, and the edited block writes back over the original selection range as a single transaction so undo collapses Selection-Focus edits to one step.

**Folding** — Mirrors code folding for prose. Two flavours collapse content out of the way: **header folding** and **selection folding**. Hovering a heading surfaces a small chevron arrow just inside the left margin (in the same gutter the line-indicator arrow uses); clicking it folds the heading's body up to the next heading of the same or higher level — folding an `# H1` hides its `## H2` / `### H3` bodies too. The heading line itself stays put and a small red **unwrap pill** (`▸ N lines`) appears beside it reporting how many lines are hidden; clicking the pill unfolds. A folded heading *also* keeps a persistent unfold arrow (pointing right) in the left-margin gutter — visible without hovering — so a section can be toggled from the arrow or the pill interchangeably. **Selection folding** works the same way: any non-empty selection shows the fold arrow beside the top of the selection (selections within a single line still surface the arrow in the same left-margin spot), and folding replaces the selected range inline with the same `▸ N lines` pill. Folds live on every editor surface that shares the base extensions — the main editor, floating panes, stack columns, and the Zen overlay. Putting the caret inside a fold's interior unfolds it (standard CodeMirror behaviour), so the fold survives a fresh fold of the section the cursor is sitting in. The command palette carries the full set: **Fold current section**, **Unfold current section**, **Fold selection** (shown only with a live selection), **Fold all sections** (collapses every heading's body to next-heading-of-any-level, leaving the whole outline visible), **Unfold all sections**, and **Fold all H1** / **Fold all H2** / **Fold all H3** (collapse every section at that level). Overlapping folds are filtered out before they're applied so nested commands can't clash.

**Notebooks** — Canvas-based visual notes with an infinite pan-and-zoom surface (25–100%); the viewport is remembered per notebook so reopening lands you back where you left off. Create text, images, drag areas, and freehand drawings on a freeform canvas. A single rounded toolbar carries every canvas tool — Select, Text, Drag Area, Brainstorm, Layers, Bookmarks, three brush slots, Slice, Erase, and Lasso — with a divider marking the hand-off between canvas tools and drawing tools. Picking any drawing tool routes input to the stroke engine — there is no separate "drawing mode" to enter. A 5 px **drag handle** runs along the bar's canvas-facing edge (the bottom edge when the bar is pinned to the top, the top edge when pinned to the bottom, the right edge when vertical); grab it to reposition the whole bar. Clicking the handle without dragging **minimizes** the toolbar — the bar hides and only the handle remains, parked 15 px in from whichever edge the bar was on; click again to restore. While dragging, three highlighted **snap zones** appear — centred on the top edge, the bottom edge, and the left edge — and releasing inside one snaps the bar there (left snaps it vertical); release anywhere else to leave it free-floating. The bar's icons shrink to ¾ size and wrap to two rows when either the parent's width or its height runs short (so a vertically-squeezed pane no longer crowds out the canvas). A **Background settings** button stays fixed to the bottom-right corner of the canvas (independent of where the toolbar sits), painted in the notebook's own background colour with a subtle sidebar-style outline; its flyout opens upward, right-aligned, so it never clips the window edge. Background settings (pattern, spacing, opacity) persist **per-notebook** — each notebook reopens with its own background instead of inheriting a global default. Strokes group, layer, pocket, and undo like every other shape. Pan with the space bar or a two-finger drag. On iPad only Apple Pencil seeds strokes — finger contacts are reserved for pan / pinch / two- and three-finger tap (undo / redo), with one extra exception: holding a finger still on the canvas while a brush, eraser, or slicer is active triggers the hold-to-select gesture and promotes the contact into a lasso. Brainstorm mode (rapid sequential text entry), a pocket shelf for stashing shapes (anchored to the right-side shelf edge), camera bookmarks (which round-trip with the notebook on save and ride sync to other devices), and 16 matching color themes round it out. Cmd-dragging text from outside the app onto a notebook canvas wraps the dropped text in a markdown blockquote and creates the resulting TextShape at 14 px instead of the configured default (Settings > Editor > Notebook text > Default size, 16 px out of the box) — handy for pasting reference quotes without follow-up formatting. Inside text shapes, markdown bullet / numbered lists hang-indent so wrapped lines align under the first character of text rather than reading as fresh entries. Holding `⌘` while dragging a shape that lives inside a drag-area grows the area live to wrap the moving cluster (selection + group + flowchart descendants) with 20 px of breathing room; releasing `⌘` contracts the area back, capped at its pre-drag bounds. **Align / distribute** keyboard shortcuts ride on the same selection: `⌘←` / `⌘→` / `⌘↑` / `⌘↓` align the selected shapes along the matching edge (left / right / top / bottom), and `⌘⇧←` / `⌘⇧→` / `⌘⇧↑` / `⌘⇧↓` distribute along the axis of the arrow — horizontal arrows distribute horizontally, vertical arrows vertically. Align needs at least two shapes selected; distribute needs three. `Cmd+C` / `Cmd+X` copy or cut the current shape selection (text, image, drag-area, draw, plus any flowchart edges between them); `Cmd+V` pastes them back in — the format is also accepted by the [Steiner](https://github.com/laffan/steiner) project so notebook clusters can be exchanged between the two apps. Selecting a single drag-area surfaces two container actions on its selection toolbar: **Arrange as grid** measures every direct child (each group counted as one unit), picks an as-square-as-possible grid (`cols = ceil(√n)`), sizes cells to the widest and tallest unit, snaps the cluster into evenly-spaced rows and columns centred on the drag-area, and resizes the drag-area to fit loosely around the result (100 px margin on every side — both grows and shrinks so cycling the column count through the flyout doesn't leave behind oversized boundaries). Group members translate by a shared delta so each group keeps its internal layout intact. A `[− N cols +]` flyout opens alongside the button — stepping the column count clamps to `1..unitCount` and re-runs the arrange so you can dial the layout up or down without re-clicking. **Reorder modes** are modal — two flavours share the same UX (solid theme-accent border replacing the dashed outline, top-of-canvas banner, ghost preview, exit with the banner's Exit button, `Esc`, or re-clicking the toolbar button). **Swap-reorder** trades the dragged unit's slot with the drop target's. **Ripple-reorder** removes the dragged unit from its reading-order slot (left-to-right, top-to-bottom, with a row-band tolerance) and re-inserts it at the target's slot, shifting every unit between them by one slot to close the gap. Both modes are group-aware (dragging any member of a grouped cluster moves the whole group, and dropping on a member of another group treats it as one unit) and show a live ghost preview — translucent clones of the actual shape contents (text, images, strokes) framed by dashed accent rectangles tracing where each side of the move will land — while the cursor hovers a valid target; drops in empty space snap back to the pre-drag location. The two modes are mutually exclusive: activating one while the other is active just switches mode. Selecting a text shape surfaces a **Colors** picker on the selection toolbar that stacks text colour, background colour, border colour, and the saved-style chips in one popup. The first two colour swatches in each row are **automatic** — they track the active theme's foreground and heading colours, so strokes and text stay on-theme when you switch styles. After those come black, white, red, light-blue, and green. Text shapes and drag areas can carry a **border** (2 px default, 10 px inner padding, 5 px border-radius) whose colour uses the same palette. The popup is sticky — try out swatches and chips freely, then dismiss with Esc or a click outside. A **+ Style** capture saves the current `{text color, background, border, size}` combo with a single click and re-applies it to any future selection (saved styles are shared across every notebook; style preview chips render the saved border), and a **Clear** button resets text colour, background, and font size back to defaults. Text shapes whose entire body is just emoji (one or several, with whitespace between) auto-rasterize into image stickers on commit so they scale, crop, and export like any other image. The right-side **shape shelf** browses every shape on the canvas (plus attached panes) — its left edge is a hover-revealed drag handle so the panel can be resized to taste, and shapes connected by flowchart edges nest under their parent so the chart reads as an outline; markdown headings inside text shapes paint in the active theme's heading colour, blockquotes (`> …`) render italic, inline `==highlights==` paint a yellow background, the row whose shape is currently selected on the canvas is tinted to match, and any `==FLAG==` markers in the full text show as 10 px coloured dots (one per unique flag) beside the row label — flag dots bubble up from text children to their parent drag-area rows. Notebooks autosave alongside documents and share the same organizational structure. Exporting a notebook opens a dedicated modal: pick scope (visible window or all content with a custom margin), format (`.hushnote`, PNG, JPG, PDF), scale (1×/2×/3×), and whether the canvas background is baked in. `.hushnote` is a single zip envelope (the same wire format Dropbox sync writes — `data.json` plus an `images/` folder for any embedded image binaries), so exporting a notebook and dragging it back into the sidebar round-trips losslessly.

**Flowchart connections** — Connect text shapes with directed arrows. Drop one or more text shapes on top of another to make them children (auto-snapped to the right of the parent, stacking under any siblings); holding `⌘` on release instead *merges* the dropped texts into the target as one node, removing the originals and their edges. From inside the inline text editor, `⌘→` commits and opens a new child, `⌘↓` opens a sibling, `⌘←` jumps to the parent, and `⌘↑` jumps back to the most-recently-edited node. Each arrow carries a small dot at its midpoint as a touch-friendly delete handle: tap the dot to reveal a `×` (mouse hover does the same), tap the `×` to remove the edge — deleting a node also removes every edge that touched it. Dragging a node pulls its descendants along so the chain stays intact. When a selected text node has children, a **Tidy** button appears on the selection toolbar to re-stack the subtree so siblings can't overlap (root stays anchored). When a stroke group is wired into the chart, the arrow anchors against the union of the whole group rather than any one stray stroke inside it.

**Wikilinks** — Obsidian-style `[[Note Title]]` references that link straight to another doc, notebook, stack, PDF, or project. Typing `[[` anywhere in a document or notebook text shape opens an inline search of every linkable note in the **active desk** (other desks are intentionally excluded so a link in Desk A can't silently resolve to a same-named note in Desk B); arrow keys move the highlight, Enter (or Tab) commits, Esc cancels, typing further narrows the list. Rendered links paint in the accent colour with a dashed underline so they read as inter-note references (broken links — pointing to a note that doesn't exist — dim and lose the underline accent); Cmd+click opens the referenced note in place from either a document or a notebook text shape (notebooks land on the canvas, docs land in the editor), and `⌘⇧`+click in a notebook text shape opens the target as a floating pane instead (drops back to "open in place" when the target is a project, since projects can't be panes). The cmd-drag pane-extract gesture still works on non-link text — wikilink clicks short-circuit only when the cursor lands on the link run itself, so dragging the body of a text shape that contains a wikilink behaves as before. When a doc or notebook is renamed every existing `[[OldName]]` reference across the library is rewritten to `[[NewName]]` so links never go stale; the in-flight rewrite covers both doc bodies and notebook text shapes and writes through to disk in the same pass.

**Floating Panes** — Cmd-drag any document or notebook from the files sidebar into the editor area to open it as a floating reference pane. Panes are fully functional editors (same markdown features, shortcuts, and syntax highlighting) that float above the main content. Resize from edges or corners, drag via the title bar, collapse to just the header, or close. Panes stay with their parent document and reappear when you return. Each doc pane has its own independent **mode context** — Focus mode, D.R.Y. mode, and Typewriter mode are toggled per-pane, not globally, so you can have sentence dimming in one pane while another shows repeat highlighting.

- **Attach** — Anchors a pane to the document scroll (docs) or canvas position (notebooks) so it moves with the content.
- **Dock** — Start dragging a pane's title bar and four blue trapezoidal drop zones surface lazily along the container's edges — each zone fades in only while the cursor is within 200 px of its matching edge (and the left zone measures from the sidebar's right edge, not the window), so the canvas isn't washed blue for the whole drag. They meet on a 45° diagonal at each corner; the one nearest the cursor lights up as you move over it, and releasing inside it docks the pane against that edge. A docked pane sits *beside* the editor rather than floating over it — it carves real estate out of the host surface (the document column, notebook canvas, stack, or PDF viewer all shrink to make room — exactly as if the window itself had become smaller along that axis), fills the full perpendicular dimension of the edge, and defaults to half the visible size on the docked axis. Side docks fill the full container height; top/bottom docks span only the width between any side docks present, and side docks shrink vertically to fit between any top/bottom docks present, so the four edges carve mutually-exclusive territory. The edge opposite the dock stays resizable; the other handles hide. **Collapsing** a docked pane shrinks its footprint to just the title bar along the dock axis (height for top/bottom docks, width for left/right) and the host surface reclaims the freed space, exactly as a collapse should — clicking the collapsed strip's title bar expands it again. Docked panes flex automatically when the window resizes or the sidebar / right-side chrome (notebook shelf, doc outline, PDF annotation shelf) opens or closes, keeping the user-set size while the rest of the layout adjusts. The editor's own right-side chrome stays associated with the editor — it slides inboard of a right-docked pane rather than hiding behind it, and the notebook shelf shrinks vertically away from any top/bottom dock. Dragging the title bar again undocks the pane back to a floating layout. Works for every pane type. **Make space for panes** is automatic now: with a single floating pane open, the edit column shifts away from whichever side the pane sits on; with two or more it stays centred so you can arrange them freely.
- **Pin** — Keeps a pane visible across document switches (blue border). Unpinning returns it to its original document. Disabled while the pane is acting as a Gutter.
- **Use as Gutter** — Header-icon toggle in every pane's title bar (also **Use Pane as Gutter** / **Stop using Pane as Gutter** in the command palette). Applies to notebook panes inside a doc context — promotes the canvas into a vertical sidebar pinned to the doc text area. The pane sits flush against the visible doc content (red border on the edge facing the text), the canvas's `camera.y` is locked to `-scrollTop` so world-y inside the canvas maps 1:1 to doc-content-y, and `camera.zoom` is locked at 1 so the comparison stays direct. Drag (space+drag or two-finger) scrolls the host doc 1:1; vertical pan in the canvas IS the doc scroll. Horizontal pan still moves `camera.x` so a wide canvas can shift sideways inside a narrow gutter. Doc headings show up as faded shadow labels with a horizontal rule above each — they track the doc headers as you type above them, and any notebook content sitting in a header's section shifts with the header so alignment is preserved. Click a shape in the notebook shelf to scroll the doc to that shape. Only the height-changing resize handles are hidden; the e / w handles stay so the user can pick a gutter width, and dragging the title bar slides the pane horizontally so its position inside the gutter zone is adjustable (vertical drag is disabled since `y` is doc-driven). Only one gutter pane per doc, and gutter panes always sit beneath other free-floating panes. Two doc-only command-palette entries pair an existing notebook (or a brand-new one) directly into gutter mode: **Add notebook as gutter** opens a fuzzy picker over notebooks in the active desk; **New notebook as gutter** prompts for a filename, creates the notebook, and pane-promotes it in one shot. Both are hidden when the active doc already carries a gutter. Scroll-driven sync is rAF-coalesced so stroke-heavy notebooks no longer jank during fast scrolls / iOS momentum, and the restored-gutter path now skips the centering rAF that previously overwrote the gutter's camera and culled the shadow headers off-screen.
- **Duplicate** — Creates a copy of a pane owned by the current document. Useful for bringing a pinned reference into a new context.
- **Real-time sync** — Edits in a pane propagate to the main editor if the same file is open, and vice versa.
- **Locked styles** — Run **Lock style to document** from the command palette on any doc or notebook to pin its current style; from then on, panes showing that file adopt the locked style (theme, font, sizing) instead of the session's active style. **Unlock style from document** clears it.
- **Cross-device sync** — Pane size, anchoring, collapsed/pinned state, and the editor scroll position round-trip to other devices via `.hush/panes.json`. Position (x/y) stays per-device since viewports differ; anything that lands off-screen on a smaller display is nudged back into view.
- **Inline panes** — Every rendered `[[wikilink]]` in a doc carries a small `▾` button. Clicking opens the linked Doc, Notebook, or Stack as a pane *embedded inside the doc* directly below the wikilink's line — the text below shifts down to make room (default 500 px tall, sized to the editor column width). Inline panes behave like normal panes (resize, collapse, close, edit) with one exception: the doc doesn't make lateral space for them — they live in the text column, not beside it. Resizing the pane grows the reserved space; closing collapses it; edits above the anchor shift the pane down naturally since it rides the wikilink's position. Dragging the title bar detaches the pane into a normal floating pane at the cursor (after which lateral make-space kicks in as if you'd dragged from the sidebar). Multiple inline panes can sit in the same doc — each `[[Title]]` occurrence is tracked independently so two references to the same note can both be open, and the layout persists across restarts via `.hush/panes.json`.

**Desktop mode** — Any document or notebook with at least one floating pane open is in "desktop" mode; the same file with no panes (or with its panes hidden) is in "file" mode. The sidebar paints a row of tiny 5 × 7 px outlined squares directly under the filename — one per pane in that file's context, lined up with the first character of the name — so you can tell at a glance which row owns the workspace you're sitting in front of. `cmd`-hovering any square shows the pane's filename (or, for a Zotero highlight pane, the paper name) in a small tooltip. Command-palette entries manage the pane set on the active doc / notebook: **Hide panes** tucks every pane in the current document off-screen (the indicator row dims to 30 % so the file is still visibly a desktop), **Show panes** brings them back, **Close all panes** closes them entirely, **Close current pane** closes just the active pane, **Copy panes to Document** clones the current pane layout into another doc/notebook in the active desk, and **Switch panes to Document** does the same plus closes the source set and opens the target so the panes ride along.

**Minimap** — Notebook-only floating widget that mirrors the open canvas at a glance. Toggle via the command palette: **Show minimap** / **Hide minimap**. The minimap renders a snapshot of the notebook with a blue rectangle showing the live viewport and translucent grey rectangles for every pane anchored to the canvas. Click or drag inside the minimap to pan the live canvas to that world point. The widget sits 10 px inboard of the shape shelf's left edge and slides with it as the shelf opens or resizes; when the minimap is shown the **Background settings** button restacks directly above it (same 10 px gap) instead of sharing its corner.

**File Management** — Multiple files with automatic 2-second autosave. Organize documents and notebooks in folders and projects with drag-and-drop reordering. The sidebar is the files panel itself — a full-height column on the left edge with the file tree in the middle, the desk switcher pinned above it, and two icon-only footer buttons (**Add** (+) and **Settings**) whose labels appear on hover. An optional **Recent Files** panel sits just above those footer buttons — enable **Show Recent Files** in Settings > General (or the Show / Hide Recent Files command-palette entries) to surface the 50 most-recently-opened files. It starts 150 px tall with a drag-to-resize top border, and each row reveals **remove** and **flag** icons on hover instead of the usual dropdown menu. A full-height **grip** on the panel's right edge owns open / close (click anywhere on the toggle area) and resize (drag the narrow strip flush against the panel's outer edge); Cmd+\\ toggles the panel too. Drag a `.md` / `.txt` file, a `.hushnote`, or a `.hushstack` from the OS into the open files sidebar to import it (PDFs are added via Zotero only) — drop on a folder / project / desk row to land it there, or on empty space to land it in the active desk's Inbox. On iPadOS the same file types are registered as document types, so tapping one in Files.app (or sharing one in from another app) opens Hush and drops the file into the active desk's Inbox — including a cold launch, since the launch URL is replayed through the same import pipeline. A small toast at the top of the window confirms success or surfaces an error message instead of failing silently. Click anywhere on a folder row (including Inbox, Images, and Trash) to toggle it open. The currently-open file is underlined in the tree — docs, notebooks, PDFs, projects, and stacks alike. The sidebar uses a crosshair cursor while navigating. Whether the panel was open and (in overlay mode) pinned rides through to the next session via per-window settings. Filenames use the full available width; a single hamburger **Menu** button overlays each row on hover (hidden during rename) and opens a labeled dropdown of the actions that apply to that row — folders / projects / Inbox lead with **New Doc** and **New Notebook** (creates inside that container), then Flag / Unflag, Rename, Use as note (docs inside projects only), Convert to project / folder, Convert to Doc (projects) / Convert to Project (standalone docs), Duplicate, Delete. A small **color palette** sits at the bottom of every row's menu — pick one of nine faded tints (or the clear swatch on the left) to paint that row's background. Children inherit a parent's tint via CSS cascade so colouring a folder also tints everything inside it; any child can override with its own pick. PDFs omit Rename (names are controlled by Zotero metadata). Items inside the Trash show only two actions: **Remove from trash** (restores the item to the Inbox) and **Permanently Delete** (prompts for confirmation, then purges from disk). The Trash folder row itself surfaces a one-entry **Empty Trash** menu. The desk-level create actions (New Doc / Notebook / Folder / Project, plus a **Local Folder** entry that mounts a folder on disk — including an iCloud Drive folder on iPad) live in the footer's **Add (+)** popover. Creating a notebook (from the Add popover or any of the New-Notebook commands) opens a small modal that prompts for the filename rather than dropping a default `New Notebook` row into the tree. Duplicating a doc or notebook prompts for confirmation and inserts the copy beside the original with a `-Copy` suffix. Folders and projects are structurally identical so a hover-revealed bi-directional arrow on each row swaps the type in place — converting a project back to a folder loses ordering and the joined preview view, so that direction asks for confirmation first. While dragging a row, the drop-target folder / project picks up a faint outline around the whole container (row + nested children) so the destination is visible at a glance, and the drag ghost anchors to the cursor's upper-left rather than centering under it so the drop indicator stays in view. The **Flagged** section of the outline view surfaces flagged items from nested folders so a flagged folder brings its children up with it. Same-type siblings can't share a name (two docs / two folders / two notebooks in the same parent would map to the same Dropbox path) so create + rename auto-suffix `Foo (2)` / `(3)` on collision. New folders / projects land in the active desk by default; new docs land in that desk's Inbox. Doc filenames track the first line of the body — when the cursor leaves line 1, on editor blur, on autosave from any other line, and after ~1.5 s of typing-idle while the cursor is still on line 1. Tabbed docs that already carry an explicit name (not "Untitled") skip auto-rename so names set by conversion or the user are preserved.

**Multi-select** — Docs, notebooks, and PDFs in the sidebar support batch selection three ways: **shift-click** ranges from the last anchor (or the active file) through the clicked row, walking the visible doc / notebook / PDF tree; **cmd / ctrl-click** toggles a single row in / out of the batch (an empty selection auto-seeds with the active file so the first cmd-click on a sibling lands a two-row batch, matching Finder); and **drag-select** arms a bounding-box selection when the pointer-down lands on any empty area of the panel (the left padding strip, between sections, below the file list) — pointer-downs on rows keep routing through the existing click + drag pipeline. Shift-drag is additive; plain drag replaces. Dragging any selected row in the sidebar carries the **whole batch** to the drop target (folder / project), Finder-style, rather than moving one file at a time. With two or more files selected the editor area swaps to a listing view that shows each entry as `Folder / Project / Filename`, with **Flag / Unflag**, **Delete**, and **Clear selection** buttons in the header. Below the file list sits the same color palette as the row menu (applies the picked tint to every selected file in one pass; mixed selections show no active swatch), then a single terse action row: **Create Stack** (name prompt → new stack populated with the selected files as columns), **Create Project** (name prompt → new project the selected docs / notebooks move into), and — when *every* selected item is a Doc — **Combine** (opens a modal where you give the new document an H1 name, re-order the sources by dragging them via a grip handle, and optionally tick **Delete originals**; confirming merges them into one new file in the active desk's Inbox where each source becomes a `---Filename---` Hush tab section beneath the H1 title, with originals moved to Trash if the box was checked). Clicking any row opens that file and clears the selection. Esc, clicking empty sidebar space, or opening any single file from anywhere (palette, picker) also clears.

**Find** — Two complementary tools. **Quick find** (`⌘F`) is a minimal, current-document-only search: a small floating bar centres at the top of the focused editor at the same vertical slot as the Google Docs sync pill (so it clears the iOS status bar / Dynamic Island and the iPadOS Control Center pull-down area), highlights every match as you type, and automatically selects the first instance at or after the cursor. Each step through the matches scrolls the active hit to the vertical centre of the editor (not just into view) so the eye lands where it already is. `⌘G` / `⌘⇧G` step through matches with wrap. The bar pins to the app's UI font so it reads consistently against the surrounding chrome regardless of the editor style. The bar is built to disappear quickly: `Enter` (or the right arrow when the caret is at the end of the input) commits the current match — closing the bar and parking the cursor on the selected hit — and `Shift+Enter` still steps backwards through matches for users who want to walk back. Pressing `⌘F` again, hitting the close `×`, or `Esc` (caught at the document level so it fires even if focus has drifted into the editor) also dismisses. Quick find is doc-shaped, so it adapts to the active surface: in a **notebook** `⌘F` opens the shape shelf and focuses its **Search** box (which filters shapes by their text) instead of a floating bar, and in a **stack** it's disabled — there's no single document to search. Shelf rows highlight the matching substring inline as the user types; rows whose hit lives outside the visible label swap the label for a `…before match after…` snippet centred on the first occurrence so the user can see why the row matched. Shelf rows also render `**bold**` runs in 600 weight (previously the asterisks rode through as literal text). A genuinely focused doc or PDF pane floating over a notebook still gets its own quick-find bar. The cross-file **Find panel** (`⌘⇧F`) mounts into the left sidebar, replacing the file list while it's open (close `×` in the upper-left of the panel restores the file tree). The panel always starts with the current document or notebook — its matches list first, with a divider below it — followed by every other doc and notebook in the active desk that has hits. Each file section is foldable (click the header or its `▶` / `▼` arrow to collapse / expand) and shows the filename above its tree path (`Folder › Project`, or the file kind for top-level entries). Result rows are two-line contextual snippets keeping **3 words before** and **8 words after** the hit, with the match `<mark>`-ed; clicking a row jumps to the file and scrolls (docs) or pans the canvas (notebooks) to the match. Editor matches are highlighted inline as you type, with the active one outlined; `Enter` / `Shift+Enter` and `⌘G` / `⌘⇧G` step through matches across every file. Selected text in the current doc, notebook text shape, or stack tile seeds the search field when either find shortcut fires. To the right of the search input sit three small toggles — **Match case** (`Aa`), **Whole word** (`Ww`), and **Regex** (`.*`). A twirl arrow to the left of the search input discloses a **replace** section: a replace input + **Global** checkbox on the first row, **Replace in Document** / **Replace in All Documents** buttons on the second (both rows indented to line up with the find input above). With Global off, results from other files dim to signal that replace will only touch the current document; checking Global applies the replacement everywhere. Notebook search is shape-scoped — each text shape's body is matched independently and clicking a notebook hit focuses that shape on the canvas (notebook replace is intentionally not wired in this pass).

**Desks** — Top-level containers above everything else in the sidebar. Each desk owns its own Inbox and Trash, and remembers two things per-desk: the active style choice (switching desks repaints the editor with that desk's saved style; the styles list itself is shared) and the last-opened file (switching desks lands the editor on whichever doc / notebook you were last working in inside that desk, falling back to the desk's first inbox item, or a fresh empty doc if the inbox is empty). New installs start with a single hidden desk so the sidebar looks just like a flat tree; the desk switcher appears the moment a second desk exists. Make new desks via the command palette (**New desk**) or by promoting a folder (**Convert folder to desk**); collapse a desk back to a folder with **Collapse desk into folder** — that one refuses while the source desk's Inbox or Trash carry items, since collapse trims those specials on the way through. The file picker (`⌘O` / **Open as pane…**) and **Send selected** target list are both scoped to the active desk so a doc in one desk can't accidentally pull a sibling from another. Desks ride Dropbox sync via a per-folder `<DeskName>/.hushdesk` file — every top-level folder under the sync root **is** a desk, and the `.hushdesk` inside carries the desk's stable cross-device id, per-desk style choice, and last-opened file. There's no global registry to drift out of step with the folder layout; renaming a desk just renames the folder, and the `.hushdesk` rides along. The last-file slot publishes Dropbox's stable `remote_id` and resolves back to a local fileId on receive (Local Sync / never-synced files ride as null and the receiving device falls back to the inbox). The active desk id stays per-device so each machine remembers where it last left off. When two devices independently create an identically-named file or desk, the receiving device auto-suffixes the duplicate (`Foo (2)`) rather than overwriting.

**Projects** — Ordered containers whose docs concatenate into one editor buffer with dashed separators between them, so a long piece can live across several files but read end-to-end. Notebooks and stacks can also be dropped into a project as supplementary material — they sort below the docs in the sidebar at 50 % opacity and stay self-contained (clicking a notebook child opens the canvas, clicking a stack child opens the stack; only docs feed the joined buffer). Nested projects and folders keep the user's custom drag order rather than being forced below the supplementary block — only notebooks, stacks, and `useAsNote` docs sink to the bottom. A **Show numbers** entry in the project's row menu prefixes its child rows with outline numbers, with dotted decimals for nested projects (1, 1.1, 1.2, 2 …). Consecutive doc rows in a project carry a short vertical connector over the gap between their icons to signal that they share one document. The `---%` end-of-document gray-out marker is scoped per file in project view, so a marker in one doc no longer dims the docs that follow. Projects and tabbed docs can be **converted back and forth**: **Convert to Doc** (sidebar menu or command palette) merges every child doc into a single document with `---Tab name---` markers separating sections; non-doc children (notebooks, stacks, PDFs) are moved to a `"[Project Name] - Files"` folder. **Convert to Project** on a document splits it at tab markers into individual child docs inside a new project. Both conversions prompt for confirmation.

**Split Headings to Files** — Break a single document apart along its own heading structure. Available both as a command-palette entry (while a doc is open) and from the **Docs** row dropdown in the sidebar (any doc, including one already inside a project). It opens a modal whose top control is a dropdown of the heading levels that actually occur in the doc (h1, h2, …); pick the level to break at and the panel below lists, live, the filenames that will be created (one per section at that level, named after each heading, with any leading content kept as a section named after the original doc). A **Convert H1s to tabs** checkbox rewrites every `# H1` line in the output to a `---H1---` Hush tab marker, and a **Delete original** checkbox moves the source doc to Trash once the split lands. For a standalone doc the result is a **new project** placed in the same container (folder / project / desk root) as the original. For a doc that already lives inside a project (where a nested project can't exist), the sections instead land as **sibling docs** directly below the source — or in its place when **Delete original** is checked.

**Versions** — Every doc and notebook accumulates timestamped snapshots automatically: docs snapshot every 30 dirty keystrokes, notebooks snapshot on each successful 2-second autosave. Run **Versions** from the command palette to browse them in a centered modal: snapshot list on the left, preview on the right. Hovering a row previews that snapshot in the preview pane immediately; clicking commits the selection and surfaces a **Restore current with…** button across the bottom — leaving a hovered row reverts to whichever snapshot is committed (or hides the preview if none is). A search input filters the list by snapshot content. A **Highlight changes** checkbox below the search (doc mode only) flips the preview into a line-level diff against the snapshot's chronological predecessor — added lines are green with a `+` gutter, removed lines are red and struck through with a `−`, unchanged lines render plain. The first snapshot in a doc has no prior to compare against, so it shows a small note above its plain content. Notebook snapshots render as a thumbnail of the canvas with a shape/layer count; the diff toggle is hidden in notebook mode. Restoring writes through to disk and re-seeds the open editor or canvas immediately so the rest of the session continues uninterrupted.

**Doc Images** — Drag any image file from the desktop into a document to embed it at the drop point, or drag an entry from the **Images** folder in the sidebar into a document or notebook. The editor renders the image inline, capped at the column width and at half the window height; narrower images are centered. Image references use standard markdown (`![alt](brown-cow.png)`) with two extensions: an optional caption after a pipe (`![alt | caption](brown-cow.png)`) and double-quoted URLs for filenames that contain spaces or parens (`![alt]("brown-cow (2).png")`). Every image is stored in a top-level **Images** folder pinned above Trash under its original filename (auto-suffixed on collision). The Images folder icon is a photo frame with a single slash through it, and — like Trash — defaults to collapsed, opening only when the user explicitly clicks it. Hovering an image row in that folder shows a tooltip preview; clicking the row — or the image in the editor — opens a full-size modal. Images can be renamed from the Files panel and every reference across every doc is rewritten automatically; deleting an image purges its refs too. Cmd-drag moves image references between panes, docs, and notebooks (a doc image dropped on a notebook canvas becomes an ImageShape; a notebook ImageShape dropped on a doc becomes markdown). Exporting a doc that contains images produces a folder with `text.md` plus an `images/` subdirectory.

**Doc Export** — Pressing Export with a document (or project) open opens a two-column modal — export controls on the left, a live preview of the document on the right. For PDF the preview *is* the real render: the Typst pipeline runs (debounced) as you adjust options and the resulting bytes are cached so pressing Export reuses the already-rendered file instead of rendering twice. Markdown (and the other text-shaped formats) shows the joined buffer as text. The modal picks **Markdown**, **PDF**, **RTF**, or — when Google Sync is connected — **Google Doc**. Markdown writes the joined buffer to disk the same way it always has — a folder with `text.md` + `images/` when the doc carries images, a bare `.md` otherwise. **RTF** converts the markdown to an RTF 1.x document (headings, bold / italic / inline code, lists, block quotes, fenced code, horizontal rules) and saves a `.rtf`. **Google Doc** (only offered once Google Sync is set up) creates a brand-new Google Doc from the content — a one-shot export that, unlike *Create Google Doc from current*, doesn't link the Hush file — and opens it in the browser. All three text formats carry **Render citations** and **Include bibliography** toggles whenever Zotero is set up and the doc cites something: *Render citations* swaps every inline `[@citekey]` (and the linked `[@citekey](zotero://…)` form) for an author-date `(Author Year)` label, and *Include bibliography* appends a `## References` section listing every cited work sorted by author surname. PDF runs the doc through [Typst](https://typst.app) in-process (no CLI, no network) so the same code path serves desktop and iOS. On iOS the modal opens with a **Filename** text input pre-populated from the doc/project name so the export can be named without renaming the file on disk first (the system share sheet has no filename field of its own). On desktop the OS save dialog already surfaces a filename slot, so the in-modal input is omitted. The PDF panel adds a **Document style** dropdown — *Formal* (white background, Libertinus Serif body, first-line indented paragraphs, generous spacing below h1/h2/h3 headings) and *Article (2 Column)* (a two-column, sans-serif magazine/journal layout in Karla, with a single-column bibliography), with the registry built so new styles can be added later — a **Line spacing** dropdown (1, 1.5, 2), a **Header size** slider (60–180 %, scales every heading level together so they keep their relationship to one another while their size *relative to the body text* tracks the slider), five layout toggles (**Strip comments** and **Strip flags**, both on by default, drop `%% … %%` blocks, `---%`-to-separator regions, and `==FLAG==` runs from the printed page; **Include tabs** on by default renders `---Tab name---` / nested `---Parent---/---Child---` markers as centred rounded pills mirroring the editor surface — uncheck to drop the markers entirely; **Number headings** off by default applies 1 / 1.1 / 1.1.1; **Page numbers** on by default centres a footer numeral), and — when Zotero is set up and the doc contains at least one `[@citekey]` reference — an **Include bibliography** toggle. Inline citations are *always* formatted: with the toggle off they render as author-date `(Author Year)` labels built straight from the reference metadata (so the prose never shows a bare citekey); with the toggle on they resolve through Typst's CSL machinery using the chosen **Bibliography style** and a sorted bibliography section is appended. Citation keys that aren't in your loaded Zotero library render as bold red `[@key]` markers inline so the gap is visible without sinking the export. The document's first line — which Hush uses as the filename — is dropped from the PDF body so the name isn't duplicated on the page (it already rides into the OS via the export filename). Projects export through the same modal — the joined buffer becomes one continuous PDF with separators replaced by paragraph breaks.

**Zotero** — Connect your Zotero library in Settings > Zotero (User ID + API key). A command-palette entry **Update Zotero References** (visible once credentials are configured) re-fetches the full library in the background — progress shows both in a small ring in the sidebar footer (to the left of the Dropbox sync icon) and in the Settings > Zotero progress bar if it's open. Three commands cover citations and reading notes:

- **Zotero: Insert reference** (`⌘⇧I`) opens a fuzzy search modal over every reference; pick the parent item or one of its attachments to insert a `[Title](zotero://...)` link, with an optional page anchor on PDFs. An **Output format** dropdown picks the link text: `Title` (`[Title](url)`), `Title (Author)` (`[Title](url) (Author)` — the link wraps just the title so the author reads as adjacent context), or `@citkey` (`[@cite](url)` — a clickable Pandoc-style citation key). The choice is remembered between inserts. Citation keys come from Better BibTeX (either the top-level `citationKey` or `Citation Key:` in `extra`) and fall back to `firstauthor + year` when neither is available. For PDF attachments an **Insert snapshot** option also rasterizes the chosen page (1500 px render, scaled to 300 px on insert, WebP at quality 90 — all configurable on the Zotero settings tab) and lands the image alongside the link. Inserts are context-aware: a doc cursor gets markdown, an active notebook text-shape edit gets the link in the textarea plus a snapshot ImageShape flush to its right, and a notebook canvas with no active edit gets a fresh TextShape (and a snapshot ImageShape if requested). Snapshots inserted into a notebook embed directly on the canvas; snapshots inserted into a doc are saved into the global Images folder so the markdown ref resolves and rides Dropbox sync. Downloaded PDFs themselves are cached locally for instant re-use across pages.
- **Zotero: Create highlight browser** opens a floating pane that lets you search a paper's PDF highlights and drag them straight into a doc or notebook. Picking a reference resolves to its PDF attachment (auto-selected if there's only one, otherwise a picker), then the pane swaps to a header with the work's title (clickable — opens the PDF in Zotero), an annotation search input, and a two-column layout: a 30 px column of color swatches on the left, the filtered annotation list on the right. A back arrow sits beside the refresh `↻` in the same pill style — click it to drop the current paper and return to the reference search. Highlight text is tidied on the way in — line breaks introduced by PDF text extraction are collapsed to single spaces, and soft-hyphenated word wraps (`hyphen-\nated` → `hyphen- ated`) drop the `- ` so the prose reads cleanly. Each row's `p. N` is a Zotero deep link too, so you can jump to the source page before deciding to use it. Drag any row out — drop into a doc to insert a markdown blockquote with comment + a `zotero://open-pdf?page=N` citation suffix, or onto a notebook canvas to spawn a TextShape with the same content. The pane behaves like every other pane (pin, attach, drag, resize) and persists across restarts; annotation results are cached locally so the Zotero API isn't pinged every time you reopen a paper, with a `↻` refresh button when you do want fresh data.
- **Zotero: Save PDF** opens the same fuzzy search over references but in a simplified flow that supports both single and batch saves. Clicking a result row opens a detail view showing its PDF attachments with **Back** and **Save PDF** buttons — clicking Save PDF downloads the binary from Zotero's API, saves it into the desk's **PDFs** folder, captures the item's metadata (title, authors, year, citekey) in `.hush/pdf.json`, and opens the PDF immediately. Each result row with a PDF also carries a **checkbox**; checking multiple items builds a batch list below the search results with an **Add N PDFs** button. Clicking Add closes the modal immediately and creates placeholder entries in the sidebar (grayed out with the `pdf-pending` style), then downloads each PDF in the background via the Rust backend — the sidebar footer's circular progress ring (shared with the Zotero reference update) fills as each download completes, and each entry transitions from pending to a normal clickable PDF. Incomplete downloads (e.g. the app was quit mid-batch) resume automatically on the next launch. The metadata powers the two-line sidebar display, the toolbar title/author, and the stack spine label. The `.hush/pdf.json` registry syncs via Dropbox so other devices automatically download the PDF in the background.

**Citations** — Typing `[@` in a document opens an inline citation search over the cached Zotero references. The popup carries its own fuzzy-search input (focus jumps straight into it, exactly like the Insert Reference modal) so you can search by title, author, year, or citekey rather than having to remember the citekey prefix; arrow keys move the highlight, Enter / Tab / click commits a `[@citekey](zotero://select/library/items/KEY)` citation, and Esc or a click outside cancels (a dismissed popup stays closed while you keep typing past the same `[@`). Citations render as tinted pills that — unlike regular links — always keep their brackets visible (`[@citekey]`); only the Zotero deep link is hidden, reappearing when the cursor enters the citation so it can be edited. Multiple citations chain with semicolons (`[@a](url);@b;@c;[@d](url)` — continuations may be bare `@key` or fully linked) and every item in the chain renders as its own pill. Hovering a citation shows a small action card: **View in Zotero** (follows the deep link, or resolves the citekey against the library), plus a PDF action — **Save PDF** downloads the reference's PDF into the desk's PDFs folder via the existing Zotero Save PDF pipeline when it isn't in Hush yet, and **View PDF** opens it once it is. The PDF action is live within a single hover: clicking Save PDF swaps the button to a spinner while the download runs and flips to View PDF the moment it lands (with a retry button if the download fails). PDF export resolves the whole chain too: chained keys emit adjacent Typst cites so they format as a single citation group.

**PDF Viewer** — PDFs are added exclusively via the **Zotero: Save PDF** command and live in a dedicated **PDFs** folder within each desk (similar to Images). The PDFs folder appears automatically when the first PDF is added and hides when empty. PDF metadata (title, authors, year, citekey) is captured from Zotero and stored in `.hush/pdf.json`, which syncs across devices via Dropbox — actual PDF binary data stays local and downloads automatically in the background when a remote device adds an entry. PDFs in the sidebar display as two-line entries: title on the first line, author and year below; the file-type icon aligns to the title line rather than centering across both lines. Pending downloads appear grayed out; clicking a pending PDF is a no-op (the viewer only opens once the binary is on disk). Click a PDF in the sidebar to open it in the main editor area; Cmd-drag it out of the sidebar to open it as a floating pane. A bottom toolbar shows the PDF's title and author centered between the controls:

- **Scroll direction toggle** — Two-icon toggle switch showing both horizontal (default) and vertical options side-by-side, with the active direction highlighted.
- **Fit toggle** (vertical scroll only) — Three-option toggle: **Fit** (single column), **Fit 2** (two pages per row), **Fit 3** (three pages per row). Hidden in horizontal mode where pages always fit the viewport height.
- **Zoom** (`−` / `+`, `⌘+=` / `⌘+-`) — Explicit percentage (50%–200%); using +/- automatically switches to fixed zoom mode. `⌘+0` resets to horizontal fit. The zoom label shows "Fit" / "Fit 2" / "Fit 3" when fitted, or the percentage when zoomed.
- **Thumbnail view** — Grid icon toggles a full-screen overlay of page thumbnails. Thumbnails are rendered asynchronously via IntersectionObserver so only visible pages (plus a buffer) are rasterized — safe for large PDFs. Each thumbnail includes annotation overlays (highlights, underlines, ink strokes). Click any thumbnail to jump to that page.

The viewer uses PDF.js with lazy page rendering via IntersectionObserver — only visible pages plus a 2-page buffer are rendered to canvas at `devicePixelRatio` resolution for sharp text on HiDPI/Retina displays; off-screen pages are freed to keep memory bounded for large PDFs. A ResizeObserver reflows pages automatically when the container changes (sidebar opens/closes, pane resizes). Inactive PDF panes are suspended to a JPEG snapshot so multiple PDFs across different documents don't hold pdfjs instances in memory simultaneously. The main viewer area tracks the sidebar inset via a MutationObserver so opening/closing the sidebar reflows the PDF width in real time. Scroll position, scroll direction, and zoom mode are saved per-PDF and restored when returning to a previously viewed file. PDF *panes* round-trip the same view state (scroll position, scroll direction, and fit / zoom mode) through `.hush/panes.json`, so a pane reopened after a document switch or an app restart lands back at the page and layout you left — the zoom mode is captured the instant you change it (not just on scroll), and the scroll position is re-asserted across a few frames so a not-yet-measured container can't clamp it back to the top.

The toolbar also shows the PDF's title and author (from Zotero metadata) centered between the layout controls and the page indicator. The same title and author appear on the spine of PDFs added to Stacks.

Hovering the bottom-right corner of any page reveals a small pop-out button; clicking it opens the PDF in the Zotero desktop app navigated to that specific page (via `zotero://open-pdf?page=N`). The toolbar also includes an **Open in Zotero ↗** link that opens the PDF at page 1. Zotero highlight and underline annotations are overlaid on pages as colored semi-transparent rectangles using position data from the API; pen/ink annotations render as SVG paths. A right-side **annotation shelf** (`⌘⇧\`, same shortcut as the doc outline and notebook shelf) lists every text annotation with colored left borders matching the highlight color — click any row to scroll the PDF to that annotation's position (works in both vertical and horizontal modes). A filter input highlights matching terms in the shelf rows. The shelf is in-flow so when open it constrains the scroll area width, keeping pages properly fitted. Its collapsed grip strip is always visible (even on a PDF with no annotations yet), so the shortcut and the click target are always reachable — an empty shelf just reads "No annotations". Panes on a PDF can be **attached to a page** — the pane anchors to a specific page position (page index + fractional offsets) so it tracks correctly through zoom changes and scroll orientation switches. The command palette entry **PDF: Update Annotations** (visible when viewing a Zotero PDF) clears cached annotations, re-fetches from the API, and re-renders both the page overlays and the shelf.

**Stacks** — Column layout that arranges docs, notebooks, PDFs, and projects on a single scrolling surface. By default stacks scroll **horizontally** (side-by-side columns); the command palette entries **Stack : Scroll vertically** and **Stack : Scroll horizontally** toggle the direction. In vertical mode each item becomes a full-width row with the spine rendered as a horizontal bar across the top — the order is file-type icon, title (horizontal text), then action buttons, left to right. The direction is persisted per-stack. Create from the sidebar's **Add (+)** menu or the command palette (**New stack**); like notebooks, a name prompt opens first. The sidebar icon is three vertical stripes. Stacks can also be opened as floating panes (Cmd-drag from the sidebar, or the "Open as pane" command). Each column has a **spine** — in horizontal mode a 50 px vertical sidebar on its left edge showing the file-type icon (top) and filename (centred, vertical text); in vertical mode a 40 px horizontal bar at the top. The spine's border darkens to indicate the active column. Clicking the spine body toggles its column open/closed; `⌘`-click closes all columns; `⌘⇧`-click opens all. Clicking the **filename** itself opens that file in the main editor instead — mirrors the floating-pane title click. Click the file-type icon to open a colour picker — picking a colour places a 30 px coloured dot behind the icon (icon turns white) and adds a **scrollbar pill** (see below); in the list-view modal the icon renders in that colour at full opacity instead. Bottom of each spine (or right side in vertical mode): drag handle (reorder), duplicate, pop-out (↗ opens as pane and removes from stack), and close (×).

- **Adding items** — (1) Option+drag any doc, notebook, PDF, or project from the sidebar into an open stack (stacks cannot be nested). (2) Command palette **Stack: Add file** opens a fuzzy picker (includes projects). (3) Floating **+** button in the bottom-right corner opens a file picker with checkboxes — click a row to add that single item instantly, or toggle checkboxes on multiple rows and press the "Add N items" button to batch-add them all. (4) **Open as Stack** in the row menu for folders and projects creates a new stack pre-populated with the container's children (warns above 15 items). When a floating pane is open in a stack context, the pane toolbar shows a **pop-in** button (↙) that adds the pane's file to the stack at the column position nearest to the pane's screen location and closes the pane.
- **Reorder** — Press the drag handle: all columns collapse to spine-only, a ghost spine follows the cursor, and a blue drop indicator shows the insertion point. On release all columns restore to their prior open/closed state.
- **Resize** — The spine's left edge is a resize handle (col-resize cursor, hover highlight). It resizes the column to the **left** of the spine. A wide trailing zone after the last column allows the final item to be resized. Max width: window width − 100 px.
- **Column content** — Doc columns use the full pane editor (same extensions and plugins as floating panes: syntax highlighting, DRY mode, typewriter, shortcuts). Each doc and project column has its own **mode context** — Focus mode, D.R.Y. mode, and Typewriter mode are toggled per-column, not globally, so one column can have focus mode active while its neighbours don't. Notebook columns mount a live `NotesCanvas` with full pan/zoom/edit and independent autosave. PDF columns load immediately via `createPdfViewer` (lazy page rendering, Zotero annotations). Project columns render their joined doc buffer with dashed separator widgets (same as the main project view) and support the heading outline sidebar. Each type's view state (doc scroll position, notebook camera, PDF scroll + zoom) is captured on virtualization and persisted in the `.hushstack` envelope. If a project in a stack is converted back to a folder, it is automatically removed from the stack.
- **Virtualisation** — Only columns within the visible viewport (plus one buffer column each side) are live-mounted. Scrolling off-screen snapshots the view state and unmounts the content; scrolling back remounts and restores.
- **Sidebars** — `⌘⇧\` toggles the active column's sidebar (doc/project outline, notebook shelf, PDF annotations). Doc and project columns get a lightweight heading outline panel embedded in the column content area; notebook and PDF columns toggle their native shelf/annotation panels. Opening a sidebar auto-widens the column; closing it narrows back. The sidebar operates at the item level, not the stack level.
- **Pane integration** — Stacks participate in the pane system (context prefix `st:`). `⌘`-drag creates floating panes above the stack as usual. **Attach** anchors a pane to the nearest stack column — the pane follows horizontal scroll and hides when its host column is collapsed, with its position measured relative to the column edge. The button label reads "Attach to stack column" in stack context.
- **Cmd+drag** — Text and image drag between stack columns works the same as between panes: `⌘`-drag a selection, text shape, or image shape from one column and drop it into another doc editor or notebook canvas within the stack, or into a floating pane. On desktop a plain drag copies and Shift-drag moves the source; on iPad (no Shift modifier) a dragged text selection always **moves** rather than leaving a duplicate behind.
- **Scrollbar pills** — When a spine colour is set, a coloured pill appears in the scrollbar track at the proportional position of that column. Open columns show the item title (canvas-measured and trimmed with an ellipsis if it overflows); collapsed columns show a round circle with the file-type icon. Clicking a pill smooth-scrolls the corresponding column to the centre of the viewport. Pills update live during resize, reorder, toggle, colour change, and viewport resize. The scrollbar is 40 px in both orientations; the native thumb is rendered beneath the pills.
- **Persistence** — Stacks are files alongside docs and notebooks, backed by a JSON file in the `.hushstack` format (items, widths, heights, names, scroll positions, camera states, PDF zoom, spine colours, scroll direction). Both scroll positions (horizontal and vertical) are saved and restored on reopen.
- **Export** — Pressing Export while a stack is open writes the `.hushstack` JSON envelope directly via the OS save dialog (desktop) or the system share sheet (iPad). Markdown / PDF aren't offered for stacks — the column layout, scroll positions, spine colours, and view state only round-trip through the native envelope.
- **List view** — A list-view button (beside the **+** button) opens a modal showing all stack items in order with drag-to-reorder handles and close buttons.

**Dropbox Sync** — Optional full-library sync to Dropbox. Connect via OAuth in Settings > Sync, choose a folder, and all documents, projects, folders, and images are mirrored automatically. Works across macOS and iOS. Documents sync as `.md` files, notebooks as `.hushnote` (zipped), images as plain binaries under each desk's `Images/` directory. PDFs are not synced as binary files — only the `.hush/pdf.json` registry travels, and each device downloads the PDF from Zotero on demand. Each top-level folder under the sync root is a desk, identified by a `<DeskName>/.hushdesk` JSON file alongside its content. Cross-device meta (project ordering, pane layout, shared styles, PDF registry) rides in `.hush/projects.json`, `.hush/panes.json`, `.hush/styles.json`, and `.hush/pdf.json`. Change detection is **longpoll-driven** — the cursor watcher blocks on `notify.dropboxapi.com` for up to 90 s and wakes within seconds of any device pushing a change, with a 60-second safety-net poll as backstop. Uploads are **rev-gated**: every push to Dropbox carries the revision we expected to overwrite, so two devices editing the same file independently can't silently clobber each other — when a clobber would have happened, the conflict prompt opens with both versions inline, and the side you don't keep is automatically snapshotted to Versions. The Sync settings tab carries: **Force sync now** (manual reconcile + cursor-pull with a progress bar), **Sync Log** (recent activity — sync failures paint red here instead of going to the developer console, so the user-facing log is the single source of truth for what went wrong), **Pending sync queue** (durable op queue showing kind, target path, attempt count, and last error per row, with a **Retry now** button), and **Clear local versions** (a recovery flow that previews what's on Dropbox — every top-level folder is shown as a desk with file counts — then wipes local state and reseeds, with a persistent progress modal that stays up until the reseed has actually finished). Clicking the small Dropbox sync icon in the sidebar footer drops straight into Settings > Sync > Dropbox so the connection, log, and recovery affordances are one click away.

**Local Sync** (desktop + iPad) — Point Hush directly at one or more folders on disk. Pick **Local Folder** from the sidebar's **Add (+)** menu to choose a location; the mount lands under a plain outline-square icon in the section beneath the active desk's normal file tree. On **iPad** the same entry opens an arbitrary folder anywhere in **iCloud Drive** (or another Files-app provider): Hush mints a security-scoped bookmark for the folder so the mount survives app relaunches, then reads and writes through it exactly like the desktop path — files autosave back to iCloud the same way they do on macOS. Each mount is attached to the desk that was active when it was added, so switching desks swaps the visible set (legacy mounts created before per-desk attachment shipped stay visible across every desk). Local Sync folders sit *outside* the version control system — Hush simply reflects the filesystem. On desktop, edits made from other apps propagate into Hush as soon as they hit disk (a filesystem watcher); on iPad there's no live watcher, so a file changed by another device refreshes the next time you bring Hush to the foreground. Either way the editor always shows the file's current on-disk contents, and Hush never writes a buffer back unless you actually edited it. Each mounted folder's hamburger menu carries **View in Finder** (macOS) / **View in Files** (iPad) to reveal the folder on disk, and an **Unlink Folder** entry that removes it from the sidebar only; nothing is changed on disk. Image files (`.png`, `.jpg`, `.svg`, etc.) sitting next to your `.md` files show up in the sidebar with hover preview, and `![](cow.png)` refs inside a Local Sync `.md` resolve to the sibling file on disk — so the file stays portable when opened by another markdown editor. Dropping an image into a Local Sync doc writes the binary next to the `.md` (auto-suffixed on collision) and inserts a relative ref. The automatic "name follows first line" rename does **not** apply to Local Sync docs — filenames on disk are the source of truth.

**Keyboard-First** — Global shortcuts work even when the app is hidden. A few editing shortcuts worth calling out (all rebindable in Settings > Shortcuts): **view fullscreen** is `⌘⌥F`; **quick find** is `⌘F` and the cross-file **Find panel** is `⌘⇧F` (see Find); `⌘G` / `⌘⇧G` step through find matches. `⌘↑` / `⌘↓` jump by paragraph, and `⌘⇧↑` / `⌘⇧↓` extend the selection to the paragraph above / below the cursor (rest-of-paragraph, not the whole document). `⌘D` / `⌘⇧D` add the next / previous occurrence of the current selection to a multi-cursor and paint every other instance with a low-opacity highlight as you step. `` ⌘` `` wraps the selection in `~~strikethrough~~` (any leading or trailing whitespace / line breaks in the selection are skipped so the markers land flush against the first and last non-blank characters; a dead-key fallback fires on layouts where the grave key is a combining accent).

**Command Palette** — Press `⌘P` to open a searchable command palette with quick access to all modes and major actions. Includes "New document" / "New notebook" plus "as pane" variants that open the new file as a floating reference without leaving the current view (every `new notebook` entry prompts for a filename via the same modal the sidebar Add popover uses). The palette is also the only home for **Styles** (one `Use Style: <name>` row per saved style plus an `Edit Styles` entry that opens a three-column modal), **Versions** (opens a modal), and **Export**. Active modes appear at the top as "Turn off" entries for fast toggling. `⌘O` jumps straight to the file picker (documents, notebooks, and projects in the active desk only); `⌘⇧O` opens the picker in "as pane" mode (panes don't host projects, so the list is filtered to docs, notebooks, PDFs, and stacks). Show / Hide Recent Files toggle the sidebar's Recent Files panel (see File Management). **Switch Desks** (palette entry plus `Ctrl+Shift+D`) opens a small picker over every desk in the library — only shows when more than one desk exists, current desk is flagged inline.

- **Create New From Selected** — takes the current selection (text in a Doc, shapes in a Notebook) and spins it out into a new file of the same type in the Inbox, named `Extracted-ddmmyy-hhmm`. Shape ids and within-selection flow edges are remapped so the extracted notebook stands on its own.
- **Send Selected** — opens a fuzzy file picker filtered to the current type (Docs in doc mode, Notebooks in notebook mode, current file excluded) and *moves* the selection to whichever target you pick: the chosen text or shapes are appended to the target and removed from the source. If the target happens to be open the live view refreshes; otherwise it's an on-disk write.
- **Stack : Scroll vertically / horizontally** — visible when a stack is open. Toggles the stack between vertical scroll (full-width rows, horizontal spine bars) and horizontal scroll (side-by-side columns, vertical spines). The non-active direction is shown; the setting is persisted per-stack.
- **Backup App Data** — bundles every doc, notebook, image, setting, and Zotero / sync cache into a single zip file. Version history (snapshots) is excluded so the archive stays small. A modal shows per-file progress while it runs and reports the destination + size when finished. iOS uses the system share sheet; desktop uses a save dialog.
- **Show Shortcuts** — opens a graphic overlay of every keyboard shortcut relevant to whatever file you're looking at (Doc, Notebook, Stack, or PDF). The list is sectioned in a fixed order — **filetype-specific first** (notebook canvas tools, PDF zoom, the doc-surface modes like Typewriter / Focus / Word count), then the **editor** shortcuts (Editing + Formatting on the CodeMirror surface), then **Panes & Panels** (sidebar / outline / shelf toggles), and finally **App-wide** (fullscreen, find, new file, Zotero, desks, plus the hard-wired `⌘P` / `⌘,` / `⌘O` openers). Shortcuts flow into responsive columns and the keys render as graphic keycaps inside square borders. Hovering any row reveals an **Edit** button that jumps straight to Settings > Shortcuts with that shortcut pre-loaded into the search field so it's the only row showing — one click from "what's the key for this?" to rebinding it. Settings > Shortcuts carries the same **filetype filter** as a dropdown beside its search box, so you can narrow the editable list to just the shortcuts that apply to Docs, Notebooks, Stacks, or PDFs.

All shortcuts are customizable in Settings.

**Window Behavior** — Floating window that stays out of the dock by default. Options to show in dock, menu bar, or both. Optional always-on-top. Fullscreen mode for immersive writing. On macOS the close / minimise / zoom traffic lights are hidden by default and fade in when the cursor enters the top-left corner of the window.

**Multiple Windows** (desktop + iPad) — Command palette entry **Open in new window** spawns another editor window seeded with whatever doc, notebook, or project you were viewing. On iPad this opens a real second iPadOS window (Split View / Slide Over / Stage Manager), using Tauri's native multi-window support; you can also long-press the app icon and pick **New Window** to open one that restores your last session. Each window keeps its own *current document*; everything else (settings, themes, file tree, styles) stays in lockstep across windows, and edits to a doc or notebook open in two windows propagate live in both directions (~250 ms for docs, on the 2 s autosave for notebooks). While more than one window is open, the files sidebar paints a small numeral chip beside the file each window has open — its background tracks the active style's text colour and the digit uses the theme's background, so it inverts cleanly across every theme. The chip is a 3 px-radius rectangle in 9 px bold.

**Touch mode** (iOS / iPadOS) — On iOS the menu (`☰`) command-palette pill is *always* visible in the bottom-left of the editor — it's the only keyboard-free path into the palette. Settings > General > Touch Mode adds three more pills above it for keyboard-free use. The lowest of those is a `⌘` key — hold it to engage the Cmd modifier on subsequent gestures (drag a file from the sidebar to spawn a pane, drag a selection between editors, drag an image ref between docs / notebooks, Cmd-merge or Cmd-click in the notebook canvas). While held, a 30 px translucent halo paints around it so you can still see the button under your thumb. Above that, a clipboard (`📋`) button pastes the system clipboard into whichever surface is currently in focus — doc editor, notebook canvas, inline text shape, or any focused input — since iPadOS virtual-keyboard Cmd+V doesn't always reach CodeMirror's paste path. The top pill is an undo (`↶`) button — in a notebook context it calls the canvas undo directly, in a doc it dispatches a synthetic Cmd+Z so CodeMirror's history keymap picks it up. The pills are anchored to the bottom-left of the viewport and slide along with the sidebar — they ride past the always-present grip strip when the panel is closed, and to the right edge of the open panel when it's open. On iPhone (narrow screens) only the palette + paste pair render, centred along the bottom edge of the viewport — the Cmd modifier and Undo paths aren't useful on a phone.

**Phone layout** (iPhone) — Phone-sized viewports get a handful of layout tweaks on top of Touch mode. The files sidebar widens to fill the screen so filenames stop getting clipped, with the grip strip resting on the panel's right border. The Settings modal collapses its left tab column into a top-of-modal dropdown so each tab gets the full width. The notebook toolbar defaults to vertical orientation (the horizontal bar overflows). Floating panes are hidden — the persisted `panesHiddenByContext` map isn't touched so iPad / desktop still see panes as usual.

**Tooltips** — Off by default for a clean reading surface. Enable **Show tooltips** in Settings > General to surface labels + shortcut hints on file-row affordances, pane headers, and notebook toolbar buttons.

**Proofread mode** — Single doc-only toggle that runs the document through the [`harper-core`](https://github.com/Automattic/harper) Rust crate and underlines spelling + grammar issues in a thick orange line. Off by default and intentionally not remembered between sessions, since the first lint after enabling it has to build harper's curated dictionary (a few seconds of work). Flip via the command palette (**Proofread mode**, the **Aa** icon with a shallow cross laid over it). The first lint runs immediately on toggle; subsequent edits are debounced to 1.5 s. A centered "Proofreading…" card stays up across the whole span between the toggle and the underlines actually painting. Hover an underline for a tooltip with the rule's message and replacement suggestions. Settings > Proofread carries a checkbox per harper rule, each with a one-line description — *Long Sentences* ships off because it's noisy for longform writing; the rest are on by default. Notebooks are intentionally skipped for now.

**Spellcheck** — Lightweight, always-fast English spellcheck. Doc-only toggle (command palette: **Spellcheck**) that paints a browser-style wavy red underline under any word the en_US Hunspell dictionary doesn't recognise. Click an underlined word to open a small popover of replacement suggestions — picking one rewrites the word in place. Backed by the [`spellbook`](https://github.com/helix-editor/spellbook) crate (pure-Rust Hunspell-format, the same engine Helix and Zed's `codebook` use); the bundled en_US dictionary loads in ~10 ms so unlike Proofread there's no warm-up modal and the toggle is **persisted between sessions**. Re-lints on a 600 ms debounce as you type. Notebooks are not lint targets.

**Trash read-only** — Opening a doc or notebook that lives in a Trash folder mounts the editor with a hard read-only lock and pins an "In the Trash — read only" banner across the top of the window. The autosave loop would otherwise quietly write changes into a file the user has already chosen to delete. Restoring the file (Remove from trash) or Permanently Deleting it clears the banner and re-enables editing.

**Google Docs paste / copy** — Pasting from Google Docs (or Word, Notion, browser selections) auto-converts the rich HTML on the clipboard to Hush-flavoured markdown: headings (`#`–`######`), `**bold**`, `*italic*`, `~~strikethrough~~`, `==highlight==`, links, blockquotes, fenced code, and ordered / unordered lists with full nesting. Plain-text pastes still flow through CodeMirror's default path untouched. Two complementary command-palette entries round-trip the other way: **Copy as Google Doc** writes the current selection (or the whole document if nothing is selected) to the clipboard as both `text/html` and `text/plain` so pasting into Google Docs preserves the formatting; **Copy as HTML** writes just the HTML source as plain text for code editors / blog drafts. `==highlights==` become `<mark style="background-color:#fff475">` and `%%comments%%` are stripped on the way out.

**Google Docs link** — Beyond paste/copy, individual Hush documents can be *linked* to a Google Doc for explicit on-demand push and pull. Setup is self-service: in **Settings > Sync > Google Sync** you paste an OAuth Client ID (and optional Secret) from your own Google Cloud project — Hush stores the credentials per install rather than shipping a shared client — then click **Connect Google account** to grant access. The auth callback lands on a one-shot loopback HTTP listener (`http://127.0.0.1:<random>`) so no `localhost` dev server has to be running for the built app to complete sign-in. From then on a doc-only command-palette entry **Link Document to Google Doc** opens a Drive picker where you can choose an existing Google Doc or create a new one with the Hush document's title; on first link a one-shot "Source of Truth" modal asks which side wins (replacing the other). A rounded pill pinned to the top of the editor column — outer edges scoped to the text column so a Gutter pane on either side stays visible — shows the linked GDoc title (clickable to open in your browser) plus three plain-text actions: **Pull** replaces the Hush document with the latest Google Doc content, **Push** replaces the Google Doc with the current Hush content, **Unlink** forgets the link without touching either document. An inline status line next to the title gives synchronous feedback during a call (`Sending…` → `Sent ✓`, `Receiving…` → `Received ✓`, or `Failed: …` on errors) so the bar is its own feedback channel — no separate toasts or confirmation prompts. Linked documents also pick up a small two-arrow badge next to their type icon in the files sidebar so it's clear at a glance which docs are connected. There is no automatic syncing or conflict detection — every sync is a deliberate, user-driven Pull or Push. **Push is non-destructive**: rather than overwriting the Google Doc, Hush diffs it against the editor at the paragraph level and applies only the paragraphs that changed (via the Docs API), so existing **comments, suggestions, and formatting on untouched text survive** — and this works across a document's tabs too. Docs with structures Hush can't yet map surgically (footnotes, tables, images, or a changed tab structure) fall back to a whole-document replace, so you're never worse off than before. Pull still replaces the Hush document wholesale; both Hush and Google Docs keep version history if you change your mind. **Import from Google Doc** creates a brand-new Hush doc from a picked GDoc and links the two automatically — the pinned link bar appears immediately and the imported doc is ready to Push / Pull against — and **Create Google Doc from current** is the inverse one-shot — pushes the active Hush doc into a brand-new Google Doc named after the file and stores the link, no picker / source-of-truth detour. The pinned link pill uses `top: calc(env(safe-area-inset-top, 0px) + 6px)` so the Push / Pull / Unlink buttons stay clear of the iOS status bar / dynamic island and remain tappable on iPad / iPhone, with a small visual gap above the pill so its suspended position reads as deliberate rather than as a header that's somehow floating in mid-air (the bar was previously anchored at `top: 0` with `viewport-fit=cover`, which let it sit under the system overlay where touches don't reach). Doc images (`![](…)`) pass through as plain markdown for now — they'll be wired up in a later pass. The auto-rename "name follows first line" rule is suppressed for linked docs so the Google Doc title stays the source of truth for the filename. Paragraph breaks round-trip cleanly: outbound HTML gives every paragraph a small space-after so paragraph spacing matches what you see in Hush (rather than collapsing flush together), and cosmetic empty-paragraph artifacts (`<p></p>`, `<p>&nbsp;</p>`, `<p><span></span></p>`) that Drive sprinkles into HTML exports are dropped on pull so the markdown doesn't accumulate phantom blank lines. A Hush `> ` quote is pushed as a once-indented paragraph and an indented paragraph is read back as a `> ` quote — the quote *style*'s own font styling (Google marks whole quotes bold) is shed on the way in, so a pulled quote carries just the `> ` marker; emphasis on part of a quote line (an explicitly bolded word) still survives.

**Google Docs tabs** — Markdown has no native concept of Google Docs tabs (the side-panel sections recently added to Docs), so Hush represents them with a custom **`---Tab name---`** marker on its own line. Nested tabs use a `/` separator inside the marker line — `---Parent---/---Child---` is a child of the `Parent` tab, `---A---/---B---/---C---` is a grandchild, and so on. Pulling a multi-tab Google Doc walks the tab tree depth-first via the Docs API and emits one marker per tab with its full path; pushing reads those markers and rebuilds the real GDoc tab structure (the root tab keeps full HTML formatting via Drive's media upload, non-root tabs are plain text since structured insertion into a specific `tabId` isn't a Drive primitive). The markers render in the editor as a compact rounded pill carrying the Google Docs glyph and a `Parent / Child` path label — cursor entering the marker line restores the raw text so the user can rename or remove it; a freshly-opened file with a marker on line 1 stays as a pill since the auto-placed caret at offset 0 doesn't count as "inside the line". The **Outline View** lists every tab in source order with a dashed-top separator, the Docs glyph, and the full path label — click to jump the editor to that marker, no fold chrome. The **files sidebar** shows the same tabs as small dimmed children under their parent doc, each with the Docs glyph at 50% opacity and the leaf name (nested tabs indent via the standard tree visuals); click to open the doc and jump. The sidebar refresh is debounced at 600 ms so rows update as the user types. **Single-tab GDocs pull as a flat document** (no spurious `---Tab 1---` marker) — markers only appear when there's actual tab structure to preserve. **Connecting Google for the first time after the tabs feature shipped requires the new `documents` OAuth scope — users connected on an older build need to Disconnect + Reconnect once in Settings > Sync > Google Sync before push/pull will succeed.**

**Google Docs comments** — Pulling a linked or imported Google Doc brings its **comments** across via the Drive Comments API, anchored to the exact text they were attached to. Placement leans on the inline comment markers Google embeds in its HTML export: each marker's reference number is paired with its comment thread through the export's footer, so a comment lands on the exact instance it was attached to even when the quoted text recurs — including a single commented period — with adjacency heuristics (tolerant of the markdown syntax the converter inserts, and of the marker sitting on either side of the range) as fallback when footer pairing can't decide. **Import asks once** whether to include comments — a small modal offers Include or Skip (just the text; the comments stay untouched in Google) — and **Pull respects that choice silently** from then on; flip it any time with the **Google : Hide comments** / **Google : Show comments** command-palette entries (Hide strips the anchors from the Hush doc and makes future Pulls skip them; Show re-fetches and weaves them back in). A comment shows in the editor as a soft amber-tinted range with no inline icon; **hover the range** to see the full note — each voice in the thread on its own line with the author's name set in bold — plus a **Resolve** button. **Suggested edits** come across via the Docs API's suggestions-inline view (exact and locale-independent): a pending deletion shows as a green-tinted range with the text in `~~strikethrough~~`, a pending insertion as a green-tinted range of the proposed text — mirroring what the Google Doc shows in Suggesting mode — and text the HTML export rendered on the other side of a suggestion is re-inserted at its context position so nothing is silently lost. Suggestions carry **Accept / Reject** buttons (hover tooltip and comments panel) instead of Resolve: accepting a deletion removes the struck text, rejecting it keeps the prose; accepting an insertion keeps the proposed text, rejecting it removes it — applied to the Hush doc only, since the API can't accept / reject the suggestion in Google itself. The note itself, and the Google comment id needed to resolve it, are stored in the markdown as a hidden `[>id]:` definition that the editor keeps out of sight; the Outline View hides the scaffolding but **paints commented runs with an amber highlight** so they're spottable from the outline too. Comment *content* is pull-only — Hush never edits a comment's text in Google, so the original anchor (and therefore the selection range) is never disturbed by a push — and **resolving acts immediately**: clicking Resolve strips the comment's syntax from the Hush doc on the spot (the commented prose stays) and resolves the comment in Google right away when the doc is linked. A **Remove all Comments** command-palette entry strips every comment from the current document in one pass without touching Google. A **comments panel** rides the left edge of the Outline View, sharing its toggle (`⌘⇧\`) — each item shows a one-line excerpt of the commented text above the full threaded note (author names bold, one line per reply), scrolls independently, and pushes the text column in rather than overlaying it. Clicking a comment selects it (amber left-edge accent — green for suggestions — plus its own Resolve button) and scrolls the document to it **without moving the cursor**; the clicked comment's range paints in a stronger tint instead, so it's findable in the text and the highlight doesn't vanish the way it would if the cursor landed inside the anchor. Comments are left out of **PDF export** entirely (the commented prose stays, the note doesn't), while Markdown export keeps the full comment syntax; footnotes (`[^id]`) now render as proper numbered footnotes in PDF.

## Installation

Requires [Rust](https://rustup.rs/) and [Node.js](https://nodejs.org/).

```sh
npm install
npm run tauri build
```

The built app will be in `src-tauri/target/release/bundle/`.

## Development

```sh
cp .env.example .env   # Configure Dropbox App Key (optional)
npm run tauri dev
```

### Dropbox Sync Setup

To enable Dropbox sync during development:

1. Create a Dropbox app at [dropbox.com/developers/apps](https://www.dropbox.com/developers/apps)
2. Add `http://localhost:5173/oauth-callback.html` as a redirect URI in the app settings
3. Copy the App Key to your `.env` file as `VITE_DROPBOX_APP_KEY`
4. For production builds, also add `hushwriter://auth/callback` as a redirect URI and set `VITE_DROPBOX_REDIRECT_URI` accordingly
