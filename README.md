# Hush

A minimal, distraction-free writing app for macOS. Hush lives in your menu bar and gives you a clean space to write — no window chrome, no clutter, just text.

## Features

**Editor** — A Markdown editor with inline syntax highlighting (headings, bold, italic, links, code), adjustable column width, and 16 color themes across light, dark, and sepia appearances. Heading `#` markers stay hidden unless your cursor is inside the heading being edited.

**Styles** — Combine theme, font, font size and line height into specific "styles" that you can easily create and move between using sidebar controls. Each style optionally overrides bg / fg / cursor / selection / **header** colour, and can mark headers as **underlined**, suppress their colour, or normalise their size. The two-column edit modal previews every change live, including the header overrides — flipping the toggle paints the matching `==FLAG==` callouts and `#` headings in the active editor and any open panes. Hovering a style row in the sidebar previews it on the active surface (doc *or* notebook canvas) without committing; inside the edit modal, hovering theme or font dropdown options previews them on the right-hand pane and snaps back when the dropdown closes.

**Post Processing** — Optional per-style overlay of decorative effects: scanlines, vignette, neon glow on text, soft drifting bloom. Off by default; users with no style configured pay nothing (no DOM, no canvas, no listeners — the entire shader runtime is dynamically imported only when a style with an enabled effect is applied). The Post Processing block in the style edit modal carries an Enable toggle, a layer dropdown (hover to preview each option live in the preview pane), a master intensity slider, and a per-layer set of knobs. Three layers ship: **Vignette + Scanlines** (CSS, static, free idle), **Phosphor Scanlines** (CSS — scanlines plus a `text-shadow` phosphor glow that reaches actual editor text via an injected stylesheet, scoped per-style), and **Neon Bloom** (WebGL2 — three soft colored glow blobs drifting slowly across the screen, screen-blended). Each layer's knobs include opacities, colors, and effect-specific settings. Animated layers pause their `requestAnimationFrame` loop while the page is hidden or the window is unfocused, so the GPU/CPU goes quiet when you tab away. A safety hook (`window.__hushShaderPanicCleanup()`) tears down every artifact (host element, injected stylesheets, scope classes, custom properties) regardless of internal state.

**Ratchet Mode** — Forward-only writing. Pick a duration (5–30 minutes) and the editor locks out deletion, selection, and all navigation. The current line is pinned to the center of the screen with previous lines scrolling up above it (typewriter-style). The cursor is always at the end of the document. The timer persists across app restarts.

**Private Mode** — Replaces all characters with opaque boxes so you can write without anyone reading over your shoulder. Toggle with `⌘⇧P`.

**Word Count** — Optional live word count pinned to the top of the text column, horizontally centered just below where the Ratchet timer appears. When Ratchet mode is also active, the count stacks directly beneath the timer in the same pill style. Counts are labelled inline so the pill stays self-explanatory: `42 words` in a regular doc, `12 section / 87 total` in a project (the doc the cursor is currently inside, then the whole project, updated as the cursor crosses separator lines). Selecting text and hovering the pill prepends a selection slot for the duration of the hover — `8 selected / 87 total` outside a project, `8 selected / 12 section / 87 total` inside one. The pill stays click-through the rest of the time so editor drag-selects aren't intercepted. Doc-mode floating panes carry their own word count next to the title (independent count per pane). Counting strips `%%…%%` comments, image markdown, and any text past the `---%` end-of-document gray-out marker so editorial notes don't inflate the total. Toggle with `⌘⇧W`.

**Typewriter Mode** — Locks the cursor to a fixed line on screen. Drag the boundary to reposition it. The document scrolls to keep the cursor in place.

**Zen Focus** — Fullscreen distraction-free writing space. Toggles with `⌘⇧S` (configurable). Available in Docs, doc panes, and notebook text shapes — picks whichever surface you're currently editing, mounts it inside a fullscreen overlay at a larger font size (Settings > Editor > Zen Focus), centres the active line vertically, fades the top and bottom thirds of the window with gradient curtains, and dims surrounding sentences via the existing focus-mode opacity setting (focus mode auto-engages on entry and restores its prior state on exit). A shortcut hint pill in the corner fades in on mouse motion. Esc or the toggle shortcut exits; the edits flow back to the source on close.

**Notebooks** — Canvas-based visual notes with an infinite pan-and-zoom surface (25–100%); the viewport is remembered per notebook so reopening lands you back where you left off. Create text, images, drag areas, and freehand drawings on a freeform canvas. A single horizontal toolbar pinned to the top of the canvas carries every canvas tool — Select, Text, Drag Area, Brainstorm, Layers, Bookmarks, three brush slots, Slice, Erase, and Lasso — with a divider marking the hand-off between canvas tools and drawing tools. Picking any drawing tool routes input to the stroke engine — there is no separate "drawing mode" to enter. Four gray pill end-caps flank the bar: a hamburger drag handle and a rotate button on the left (drag = move the whole assembly, rotate = flip between horizontal and vertical orientation), and a Background settings button plus a Collapse tab on the right (collapse hides everything except the drag handle, the currently active tool, and the collapse tab itself — tap again to expand). When the bar is vertical, every popup follows the same proximity rule and swings to whichever side is farthest from the closest screen edge. Strokes group, layer, pocket, and undo like every other shape. Pan with the space bar or a two-finger drag. On iPad only Apple Pencil seeds strokes — finger contacts are reserved for pan / pinch / two- and three-finger tap (undo / redo), with one extra exception: holding a finger still on the canvas while a brush, eraser, or slicer is active triggers the hold-to-select gesture and promotes the contact into a lasso. Brainstorm mode (rapid sequential text entry), a pocket shelf for stashing shapes, camera bookmarks (which round-trip with the notebook on save and ride sync to other devices), and 16 matching color themes round it out. Cmd-dragging text from outside the app onto a notebook canvas wraps the dropped text in a markdown blockquote and creates the resulting TextShape at 14 px instead of the default 18 px — handy for pasting reference quotes without follow-up formatting. Inside text shapes, markdown bullet / numbered lists hang-indent so wrapped lines align under the first character of text rather than reading as fresh entries. Holding `⌘` while dragging a shape that lives inside a drag-area grows the area live to wrap the moving cluster (selection + group + flowchart descendants) with 20 px of breathing room; releasing `⌘` contracts the area back, capped at its pre-drag bounds. `Cmd+C` / `Cmd+X` copy or cut the current shape selection (text, image, drag-area, draw, plus any flowchart edges between them); `Cmd+V` pastes them back in — the format is also accepted by the [Steiner](https://github.com/laffan/steiner) project so notebook clusters can be exchanged between the two apps. Selecting a text shape surfaces a **Colors** picker on the selection toolbar that stacks text colour, background colour, and the saved-style chips in one popup. The popup is sticky — try out swatches and chips freely, then dismiss with Esc or a click outside. A **+ Style** capture saves the current `{text color, background, size}` combo with a single click and re-applies it to any future selection (saved styles are shared across every notebook), and a **Clear** button resets text colour, background, and font size back to defaults. Text shapes whose entire body is just emoji (one or several, with whitespace between) auto-rasterize into image stickers on commit so they scale, crop, and export like any other image. The right-side **shape shelf** browses every shape on the canvas (plus attached panes) — its left edge is a hover-revealed drag handle so the panel can be resized to taste, and shapes connected by flowchart edges nest under their parent so the chart reads as an outline; markdown headings inside text shapes paint in the active theme's heading colour, blockquotes (`> …`) render italic, inline `==highlights==` paint a yellow background, and the row whose shape is currently selected on the canvas is tinted to match. Notebooks autosave alongside documents and share the same organizational structure. Exporting a notebook opens a dedicated modal: pick scope (visible window or all content with a custom margin), format (`.hushnote`, PNG, JPG, PDF), scale (1×/2×/3×), and whether the canvas background is baked in.

**Flowchart connections** — Connect text shapes with directed arrows. Drop one or more text shapes on top of another to make them children (auto-snapped to the right of the parent, stacking under any siblings); holding `⌘` on release instead *merges* the dropped texts into the target as one node, removing the originals and their edges. From inside the inline text editor, `⌘→` commits and opens a new child, `⌘↓` opens a sibling, `⌘←` jumps to the parent, and `⌘↑` jumps back to the most-recently-edited node. Each arrow carries a small dot at its midpoint as a touch-friendly delete handle: tap the dot to reveal a `×` (mouse hover does the same), tap the `×` to remove the edge — deleting a node also removes every edge that touched it. Dragging a node pulls its descendants along so the chain stays intact. When a selected text node has children, a **Tidy** button appears on the selection toolbar to re-stack the subtree so siblings can't overlap (root stays anchored). When a stroke group is wired into the chart, the arrow anchors against the union of the whole group rather than any one stray stroke inside it.

**Floating Panes** — Cmd-drag any document or notebook from the files sidebar into the editor area to open it as a floating reference pane. Panes are fully functional editors (same markdown features, shortcuts, and syntax highlighting) that float above the main content. Resize from edges or corners, drag via the title bar, collapse to just the header, or close. Panes stay with their parent document and reappear when you return.

- **Attach** — Anchors a pane to the document scroll (docs) or canvas position (notebooks) so it moves with the content.
- **Pin** — Keeps a pane visible across document switches (blue border). Unpinning returns it to its original document.
- **Duplicate** — Creates a copy of a pane owned by the current document. Useful for bringing a pinned reference into a new context.
- **Real-time sync** — Edits in a pane propagate to the main editor if the same file is open, and vice versa.
- **Locked styles** — Run **Lock style to document** from the command palette on any doc or notebook to pin its current style; from then on, panes showing that file adopt the locked style (theme, font, sizing) instead of the session's active style. **Unlock style from document** clears it.
- **Cross-device sync** — Pane size, anchoring, collapsed/pinned state, and the editor scroll position round-trip to other devices via `.hush/panes.json`. Position (x/y) stays per-device since viewports differ; anything that lands off-screen on a smaller display is nudged back into view.

**Desktop mode** — Any document or notebook with at least one floating pane open is in "desktop" mode; the same file with no panes (or with its panes hidden) is in "file" mode. The sidebar paints a row of tiny 5 × 7 px outlined squares directly under the filename — one per pane in that file's context, lined up with the first character of the name — so you can tell at a glance which row owns the workspace you're sitting in front of. `cmd`-hovering any square shows the pane's filename (or, for a Zotero highlight pane, the paper name) in a small tooltip. Five command-palette entries manage the pane set on the active doc / notebook: **Hide panes** tucks every pane in the current document off-screen (the indicator row dims to 30 % so the file is still visibly a desktop), **Show panes** brings them back, **Clear panes** closes them entirely, **Copy panes to Document** clones the current pane layout into another doc/notebook in the active desk, and **Switch panes to Document** does the same plus closes the source set and opens the target so the panes ride along.

**Minimap** — Notebook-only floating widget that mirrors the open canvas at a glance. Toggle via the command palette: **Show minimap** / **Hide minimap**. The minimap renders a snapshot of the notebook with a blue rectangle showing the live viewport and translucent grey rectangles for every pane anchored to the canvas. Click or drag inside the minimap to pan the live canvas to that world point.

**File Management** — Multiple files with automatic 2-second autosave. Organize documents and notebooks in folders and projects with drag-and-drop reordering. Drag a `.md` / `.txt` file or a `.hushnote` from the OS into the open files sidebar to import it — drop on a folder / project / desk row to land it there, or on empty space to land it in the active desk's Inbox. Click anywhere on a folder row (including Inbox, Images, and Trash) to toggle it open. The sidebar uses a crosshair cursor while navigating and its width can be resized by dragging its right edge — the handle is invisible until you approach it, matching the editor's column resizers. Filenames use the full available width; per-row action buttons overlay the title only on hover and hide themselves during rename. Duplicating a doc or notebook prompts for confirmation and inserts the copy beside the original with a `-Copy` suffix. Folders and projects are structurally identical so a hover-revealed bi-directional arrow on each row swaps the type in place — converting a project back to a folder loses ordering and the joined preview view, so that direction asks for confirmation first. The **Flagged** section of the outline view surfaces flagged items from nested folders so a flagged folder brings its children up with it. Same-type siblings can't share a name (two docs / two folders / two notebooks in the same parent would map to the same Dropbox path) so create + rename auto-suffix `Foo (2)` / `(3)` on collision. New folders / projects land in the active desk by default; new docs land in that desk's Inbox. Doc filenames track the first line of the body — when the cursor leaves line 1, on editor blur, on autosave from any other line, and after ~1.5 s of typing-idle while the cursor is still on line 1.

**Desks** — Top-level containers above everything else in the sidebar. Each desk owns its own Inbox and Trash, and remembers two things per-desk: the active style choice (switching desks repaints the editor with that desk's saved style; the styles list itself is shared) and the last-opened file (switching desks lands the editor on whichever doc / notebook you were last working in inside that desk, falling back to the desk's first inbox item, or a fresh empty doc if the inbox is empty). New installs start with a single hidden desk so the sidebar looks just like a flat tree; the desk switcher appears the moment a second desk exists. Make new desks via the command palette (**New desk**) or by promoting a folder (**Convert folder to desk**); collapse a desk back to a folder with **Collapse desk into folder** — that one refuses while the source desk's Inbox or Trash carry items, since collapse trims those specials on the way through. The file picker (`⌘O` / **Open as pane…**) and **Send selected** target list are both scoped to the active desk so a doc in one desk can't accidentally pull a sibling from another. Desks ride Dropbox sync via a per-folder `<DeskName>/.hushdesk` file — every top-level folder under the sync root **is** a desk, and the `.hushdesk` inside carries the desk's stable cross-device id, per-desk style choice, and last-opened file. There's no global registry to drift out of step with the folder layout; renaming a desk just renames the folder, and the `.hushdesk` rides along. The last-file slot publishes Dropbox's stable `remote_id` and resolves back to a local fileId on receive (Local Sync / never-synced files ride as null and the receiving device falls back to the inbox). The active desk id stays per-device so each machine remembers where it last left off. When two devices independently create an identically-named file or desk, the receiving device auto-suffixes the duplicate (`Foo (2)`) rather than overwriting.

**Projects** — Ordered containers whose docs concatenate into one editor buffer with dashed separators between them, so a long piece can live across several files but read end-to-end. Notebooks can also be dropped into a project as supplementary material — they sort below the docs in the sidebar at 50 % opacity and stay self-contained (clicking a notebook child opens the canvas; only docs feed the joined buffer). Consecutive doc rows in a project carry a short vertical connector over the gap between their icons to signal that they share one document. The `---%` end-of-document gray-out marker is scoped per file in project view, so a marker in one doc no longer dims the docs that follow.

**Versions** — Every doc and notebook accumulates timestamped snapshots automatically: docs snapshot every 30 dirty keystrokes, notebooks snapshot on each successful 2-second autosave. Open the **Versions** panel from the sidebar to browse them. Hovering a row previews that snapshot in the editor area immediately; clicking commits the selection and surfaces a **Restore current with…** button across the bottom of the preview — leaving a hovered row reverts to whichever snapshot is committed (or hides the preview if none is). A search input filters the list by snapshot content. A **Highlight changes** checkbox below the search (doc mode only) flips the preview into a line-level diff against the snapshot's chronological predecessor — added lines are green with a `+` gutter, removed lines are red and struck through with a `−`, unchanged lines render plain. The first snapshot in a doc has no prior to compare against, so it shows a small note above its plain content. Notebook snapshots render as a thumbnail of the canvas with a shape/layer count; the diff toggle is hidden in notebook mode. Restoring writes through to disk and re-seeds the open editor or canvas immediately so the rest of the session continues uninterrupted.

**Doc Images** — Drag any image file from the desktop into a document to embed it at the drop point, or drag an entry from the **Images** folder in the sidebar into a document or notebook. The editor renders the image inline, capped at the column width and at half the window height; narrower images are centered. Image references use standard markdown (`![alt](brown-cow.png)`) with two extensions: an optional caption after a pipe (`![alt | caption](brown-cow.png)`) and double-quoted URLs for filenames that contain spaces or parens (`![alt]("brown-cow (2).png")`). Every image is stored in a top-level **Images** folder pinned above Trash under its original filename (auto-suffixed on collision). The Images folder icon is a photo frame with a single slash through it, and — like Trash — defaults to collapsed, opening only when the user explicitly clicks it. Hovering an image row in that folder shows a tooltip preview; clicking the row — or the image in the editor — opens a full-size modal. Images can be renamed from the Files panel and every reference across every doc is rewritten automatically; deleting an image purges its refs too. Cmd-drag moves image references between panes, docs, and notebooks (a doc image dropped on a notebook canvas becomes an ImageShape; a notebook ImageShape dropped on a doc becomes markdown). Exporting a doc that contains images produces a folder with `text.md` plus an `images/` subdirectory.

**Zotero** — Connect your Zotero library in Settings > Zotero (User ID + API key). Two commands cover citations and reading notes:

- **Zotero: Insert reference** (`⌘⇧I`) opens a fuzzy search modal over every reference; pick the parent item or one of its attachments to insert a `[Title](zotero://...)` link, with an optional page anchor on PDFs. An **Output format** dropdown picks the link text: `Title` (`[Title](url)`), `Title (Author)` (`[Title](url) (Author)` — the link wraps just the title so the author reads as adjacent context), or `@citkey` (`[@cite](url)` — a clickable Pandoc-style citation key). The choice is remembered between inserts. Citation keys come from Better BibTeX (either the top-level `citationKey` or `Citation Key:` in `extra`) and fall back to `firstauthor + year` when neither is available. For PDF attachments an **Insert snapshot** option also rasterizes the chosen page (1500 px render, scaled to 300 px on insert, WebP at quality 90 — all configurable on the Zotero settings tab) and lands the image alongside the link. Inserts are context-aware: a doc cursor gets markdown, an active notebook text-shape edit gets the link in the textarea plus a snapshot ImageShape flush to its right, and a notebook canvas with no active edit gets a fresh TextShape (and a snapshot ImageShape if requested). Snapshots inserted into a notebook embed directly on the canvas; snapshots inserted into a doc are saved into the global Images folder so the markdown ref resolves and rides Dropbox sync. Downloaded PDFs themselves are cached locally for instant re-use across pages.
- **Zotero: Create highlight browser** opens a floating pane that lets you search a paper's PDF highlights and drag them straight into a doc or notebook. Picking a reference resolves to its PDF attachment (auto-selected if there's only one, otherwise a picker), then the pane swaps to a header with the work's title (clickable — opens the PDF in Zotero), an annotation search input, and a two-column layout: a 30 px column of color swatches on the left, the filtered annotation list on the right. A back arrow sits beside the refresh `↻` in the same pill style — click it to drop the current paper and return to the reference search. Highlight text is tidied on the way in — line breaks introduced by PDF text extraction are collapsed to single spaces, and soft-hyphenated word wraps (`hyphen-\nated` → `hyphen- ated`) drop the `- ` so the prose reads cleanly. Each row's `p. N` is a Zotero deep link too, so you can jump to the source page before deciding to use it. Drag any row out — drop into a doc to insert a markdown blockquote with comment + a `zotero://open-pdf?page=N` citation suffix, or onto a notebook canvas to spawn a TextShape with the same content. The pane behaves like every other pane (pin, attach, drag, resize) and persists across restarts; annotation results are cached locally so the Zotero API isn't pinged every time you reopen a paper, with a `↻` refresh button when you do want fresh data.

**Dropbox Sync** — Optional full-library sync to Dropbox. Connect via OAuth in Settings > Sync, choose a folder, and all documents, projects, folders, and images are mirrored automatically. Works across macOS and iOS. Documents sync as `.md` files, notebooks as `.hushnote` (zipped), images as plain binaries under each desk's `Images/` directory. Each top-level folder under the sync root is a desk, identified by a `<DeskName>/.hushdesk` JSON file alongside its content. Cross-device meta (project ordering, pane layout, shared styles) rides in `.hush/projects.json`, `.hush/panes.json`, and `.hush/styles.json`. Sync is bidirectional with automatic conflict resolution. The Sync settings tab carries three explicit actions: **Force sync now** (manual reconcile + cursor-pull with a progress bar so it's not silent background work) and **Clear local versions** (a recovery flow that previews what's on Dropbox — every top-level folder is shown as a desk with file counts — then wipes local state and reseeds, with a persistent progress modal that stays up until the reseed has actually finished).

**Local Sync** (desktop only) — A second Sync section lets you point Hush directly at one or more folders on disk. Click **Add folder** to pick a location; the folder and its contents appear in the sidebar under a dedicated icon (a circle with a horizontal line through it). Local Sync folders sit *outside* the version control system — Hush simply reflects the filesystem. Edits made from other apps propagate into Hush as soon as they hit disk, and edits inside Hush write straight back. Unsyncing a Local Sync folder removes it from the sidebar only; nothing is changed on disk. Image files (`.png`, `.jpg`, `.svg`, etc.) sitting next to your `.md` files show up in the sidebar with hover preview, and `![](cow.png)` refs inside a Local Sync `.md` resolve to the sibling file on disk — so the file stays portable when opened by another markdown editor. Dropping an image into a Local Sync doc writes the binary next to the `.md` (auto-suffixed on collision) and inserts a relative ref.

**Keyboard-First** — Global shortcuts work even when the app is hidden:

**Command Palette** — Press `⌘P` to open a searchable command palette with quick access to all modes and major actions. Includes "New document" / "New notebook" plus "as pane" variants that open the new file as a floating reference without leaving the current view. Active modes appear at the top as "Turn off" entries for fast toggling. `⌘O` jumps straight to the file picker (documents, notebooks, and projects in the active desk only); `⌘⇧O` opens the picker in "as pane" mode (panes don't host projects, so the list is filtered to docs and notebooks only).

- **Create New From Selected** — takes the current selection (text in a Doc, shapes in a Notebook) and spins it out into a new file of the same type in the Inbox, named `Extracted-ddmmyy-hhmm`. Shape ids and within-selection flow edges are remapped so the extracted notebook stands on its own.
- **Send Selected** — opens a fuzzy file picker filtered to the current type (Docs in doc mode, Notebooks in notebook mode, current file excluded) and *moves* the selection to whichever target you pick: the chosen text or shapes are appended to the target and removed from the source. If the target happens to be open the live view refreshes; otherwise it's an on-disk write.
- **Backup App Data** — bundles every doc, notebook, image, setting, and Zotero / sync cache into a single zip file. Version history (snapshots) is excluded so the archive stays small. A modal shows per-file progress while it runs and reports the destination + size when finished. iOS uses the system share sheet; desktop uses a save dialog.

All shortcuts are customizable in Settings.

**Window Behavior** — Floating window that stays out of the dock by default. Options to show in dock, menu bar, or both. Optional always-on-top. Fullscreen mode for immersive writing.

**Multiple Windows** (desktop only) — Command palette entry **Open in new window** spawns another editor window seeded with whatever doc, notebook, or project you were viewing. Each window keeps its own *current document*; everything else (settings, themes, file tree, styles) stays in lockstep across windows, and edits to a doc or notebook open in two windows propagate live in both directions (~250 ms for docs, on the 2 s autosave for notebooks). While more than one window is open, the files sidebar paints a small numeral chip beside the file each window has open — its background tracks the active style's text colour and the digit uses the theme's background, so it inverts cleanly across every theme. The chip is a 3 px-radius rectangle in 9 px bold.

**Touch mode** (iOS / iPadOS) — Settings > General toggles a stack of four floating buttons in the bottom-left of the editor for keyboard-free use. The lowest pill is a `⌘` key — hold it to engage the Cmd modifier on subsequent gestures (drag a file from the sidebar to spawn a pane, drag a selection between editors, drag an image ref between docs / notebooks, Cmd-merge or Cmd-click in the notebook canvas). While held, a 30 px translucent halo paints around it so you can still see the button under your thumb. The next pill up is a menu (`☰`) button that opens the command palette on tap. Above that, a clipboard (`📋`) button pastes the system clipboard into whichever surface is currently in focus — doc editor, notebook canvas, inline text shape, or any focused input — since iPadOS virtual-keyboard Cmd+V doesn't always reach CodeMirror's paste path. The top pill is an undo (`↶`) button — in a notebook context it calls the canvas undo directly, in a doc it dispatches a synthetic Cmd+Z so CodeMirror's history keymap picks it up. All four pills mirror the sidebar-toggle's geometry — they slide alongside the panel as it opens. On iPhone (narrow screens) only the palette + paste pair render, centred along the bottom edge of the viewport — the Cmd modifier and Undo paths aren't useful on a phone.

**Phone layout** (iPhone) — Phone-sized viewports get a handful of layout tweaks on top of Touch mode. The files / styles / versions sidebar widens to fill the screen so filenames stop getting clipped, with the floating panel toggle resting on the panel's right border. The Settings modal collapses its left tab column into a top-of-modal dropdown so each tab gets the full width. The notebook toolbar defaults to vertical orientation (the horizontal bar overflows). Floating panes are hidden — the persisted `panesHiddenByContext` map isn't touched so iPad / desktop still see panes as usual.

**Tooltips** — Off by default for a clean reading surface. Enable **Show tooltips** in Settings > General to surface labels + shortcut hints on every sidebar, pane header, and notebook toolbar button.

**Proofread mode** — Single doc-only toggle that runs the document through the [`harper-core`](https://github.com/Automattic/harper) Rust crate and underlines spelling + grammar issues in a thick orange line. Off by default and intentionally not remembered between sessions, since the first lint after enabling it has to build harper's curated dictionary (a few seconds of work). Flip via the command palette (**Proofread mode**, the **Aa** icon with a shallow cross laid over it). The first lint runs immediately on toggle; subsequent edits are debounced to 1.5 s. A centered "Proofreading…" card stays up across the whole span between the toggle and the underlines actually painting. Hover an underline for a tooltip with the rule's message and replacement suggestions. Settings > Proofread carries a checkbox per harper rule, each with a one-line description — *Long Sentences* ships off because it's noisy for longform writing; the rest are on by default. Notebooks are intentionally skipped for now.

**Google Docs paste / copy** — Pasting from Google Docs (or Word, Notion, browser selections) auto-converts the rich HTML on the clipboard to Hush-flavoured markdown: headings (`#`–`######`), `**bold**`, `*italic*`, `~~strikethrough~~`, `==highlight==`, links, blockquotes, fenced code, and ordered / unordered lists with full nesting. Plain-text pastes still flow through CodeMirror's default path untouched. Two complementary command-palette entries round-trip the other way: **Copy as Google Doc** writes the current selection (or the whole document if nothing is selected) to the clipboard as both `text/html` and `text/plain` so pasting into Google Docs preserves the formatting; **Copy as HTML** writes just the HTML source as plain text for code editors / blog drafts. `==highlights==` become `<mark style="background-color:#fff475">` and `%%comments%%` are stripped on the way out.

**Google Docs link** — Beyond paste/copy, individual Hush documents can be *linked* to a Google Doc for explicit on-demand push and pull. Setup is self-service: in **Settings > Sync > Google Sync** you paste an OAuth Client ID (and optional Secret) from your own Google Cloud project — Hush stores the credentials per install rather than shipping a shared client — then click **Connect Google account** to grant access. The auth callback lands on a one-shot loopback HTTP listener (`http://127.0.0.1:<random>`) so no `localhost` dev server has to be running for the built app to complete sign-in. From then on a doc-only command-palette entry **Link Document to Google Doc** opens a Drive picker where you can choose an existing Google Doc or create a new one with the Hush document's title; on first link a one-shot "Source of Truth" modal asks which side wins (replacing the other). A thin bar pinned to the top of the editor column shows the linked GDoc title (clickable to open in your browser) plus three plain-text actions: **Pull** replaces the Hush document with the latest Google Doc content, **Push** replaces the Google Doc with the current Hush content, **Unlink** forgets the link without touching either document. An inline status line next to the title gives synchronous feedback during a call (`Sending…` → `Sent ✓`, `Receiving…` → `Received ✓`, or `Failed: …` on errors) so the bar is its own feedback channel — no separate toasts or confirmation prompts. Linked documents also pick up a small two-arrow badge next to their type icon in the files sidebar so it's clear at a glance which docs are connected. There is no automatic syncing or conflict detection — every push and pull is a deliberate, full-document replace; both Hush and Google Docs keep version history if you change your mind. **Import from Google Doc** is also available as a one-shot (creates a new unlinked Hush doc from a picked GDoc). Doc images (`![](…)`) pass through as plain markdown for now — they'll be wired up in a later pass.

### Dropbox Sync Setup

To enable Dropbox sync during development:

1. Create a Dropbox app at [dropbox.com/developers/apps](https://www.dropbox.com/developers/apps)
2. Add `http://localhost:5173/oauth-callback.html` as a redirect URI in the app settings
3. Copy the App Key to your `.env` file as `VITE_DROPBOX_APP_KEY`
4. For production builds, also add `hushwriter://auth/callback` as a redirect URI and set `VITE_DROPBOX_REDIRECT_URI` accordingly
