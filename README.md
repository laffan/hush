# Hush

A minimal, distraction-free writing app for macOS and iPad. Hush lives in your menu bar and gives you a clean space to write — no window chrome, no clutter, just text. Everything is reachable from the keyboard, and almost everything happens through the command palette (`⌘P`).

Under the minimal surface is a full writing system: a Markdown editor, canvas-based visual notebooks, a flexible organizational model, research tools built around Zotero and PDFs, and file-based sync that works with any folder provider you already use.

## Writing

**The editor** is Markdown with inline rendering — headings, bold/italic, links, tables, images, footnotes, callouts, YAML properties, and `[[wikilinks]]` between notes. Sixteen color themes across light, dark, and sepia, and **Styles** that bundle theme + font + colors into presets you can switch, share, and import as JSON. Every colour in the style editor opens an in-app picker — a rainbow hue slider, an opacity slider and a saturation/brightness field — so the live preview stays visible while you tune. The opacity slider is there on every one: the palette, the caret and its glow, the line indicator's custom colour, gradient nodes, WebGL and caret effects, and post-processing colours. A style's **Line Indicator** marks the line you are on — arrows, a border, an underline or a highlighter wash — in the caret's colour or one of its own for each appearance; the underline and the highlighter also take a **thickness** (the underline's rule in pixels, the highlighter's band as a share of the line, rising from its foot) and a **width**, Normal for the text column or Full width for the whole editor. A style's **Cursor** section sets the caret's shape — the system caret, a block, an underline or a 3px line — and its colour for the light and dark appearances side by side. A custom caret also has an **Idle Animation** — the usual blink, a slow pulse between 20% and full opacity, or none — and can carry a **glow** in a colour of its own, switched on separately for the light and dark appearances, with an intensity slider that sets how far the halo spreads. The preview pane plays the idle animation the editor will.

A style also carries two stacks of layers, both built the same way — add, reorder by dragging, hide, delete:

- **Background** sits behind the text: images, animatable multi-node gradients, WebGL effects, and caret effects that follow your cursor as you type (sparks, a fading underline glow, a phosphor flicker bar). Every caret effect has its own colour, blend mode and opacity for light and for dark — or set it to match your caret — plus an anti-alias toggle and its own shape controls (spark height, underline thickness, trail length, vertical offset).
- **Post Processing** sits over the whole window: vignette, text glow, scan lines, tint, grayscale, sepia, and a window-opacity slider that makes Hush itself translucent so whatever is behind it shows through. Mix as many as you like, in any order.

**Focus tools** keep you in the text:

- **Focus Mode** (`⌘S`) dims everything but the current sentence — the sidebars, the word count, the clock and the iPad touch-mode buttons fade to the same level, and headings, highlights and the YOUAREHERE tag go monochrome everywhere but the sentence you are in; **Typewriter Mode** pins the cursor to a fixed line. Whatever the mode, a document never has to be written at the bottom edge of the screen: there is always room below its last line to scroll that line up to the middle of the window — or of the pane or stack column it is open in. The room is space, not blank lines; nothing is added to the file.
- **Zen Focus** (`⌘⇧S`) is a fullscreen writing overlay with the current line centered and the edges of the screen faded away — text blurs behind frosted glass as soon as it leaves the centered lines, more strongly toward the edges. The pill at the bottom of the window (bring the pointer down to it) sets the dim, the font size, the blur (off up to five times the default) and how many lines stay centered. The command palette, Settings and the style editor open over it. Cards stay out of it: their markdown is folded away as it is in the Doc, but no card is drawn in Zen, pinned or not.
- **Private Mode** (`⌘⇧P`) blacks out every word on screen so you can write in public — bars painted over the text rather than substituted for it, so nothing reflows and the page you were reading stays where it was. A dummy-document mode swaps the letters for plausible ones instead. Both cover every surface currently on screen: floating panes, stack columns and the Zen overlay, not just the editor.
- **Word count** (`⌘⇧W`), an optional live pill above the text column — it stays centred over the column when a pane, the sidebar or the Overview moves it.
- **Set word count limit** caps a single document. Pick a number from the command palette — never fewer words than the document already holds — and the document takes no new word once it reaches that number. The word you are in the middle of is still yours to finish — a half-typed word already counts as a word, so the cap is often reached mid-word — but the space after it is refused, and so is anything else that would start another one. Below the cap a paste that overshoots lands trimmed to the words that still fit; at it, a paste lands nothing. Deleting and rewriting are untouched: the wall is on adding, not on editing. The cap shows itself through the word count rather than in an indicator of its own: `320 / 500 words`, red for the last ten, `500 - limit reached` at the cap — and those last ten put the count on screen whether or not you keep it switched on. The cap belongs to the document, so a floating pane, a stack column or Zen Focus showing that doc holds the same line. Run the command again to change the number; **Clear word count limit** lifts it.

**Revision tools** help you rework what you wrote:

- **Selection Focus** opens the current selection alone in a fullscreen editor; edits write back as one undo step.
- **The Shuffle Editor** (`⌘⇧E`) explodes a selection into draggable sentences you can reorder, merge, strike, or comment, then compare against the original before committing.
- **Folding** collapses sections or selections behind small pills, like code folding for prose. Heading folds nest: folding a heading folds every subheading inside it too, so opening an H1 shows its H2s, still folded, each holding its H3s. **Fold all sections** leaves only the outermost headings in view.
- **Horizontal rules** — a `---` on a line of its own (or `***`, `___`) — draw as a thin line centred on the row, 70% of the column's width. Put the caret on the row to edit the markdown.
- Sentence-level navigation and editing shortcuts: jump, select, and move whole sentences from the keyboard. **⌘⌫** deletes the sentence the cursor is in — the one ⌘L would select, so at the end of a paragraph it takes the paragraph's last sentence — along with the space it leaves behind. A cursor inside a parenthetical means the parenthetical first: ⌘L selects the `(…)`, and pressed again selects the sentence around it; ⌘⌫ deletes the `(…)` and leaves the sentence for the next press. That applies only to where you start — once a sentence is selected, ⌘L grows sentence by sentence and passes over other parentheticals like any other text. Closing markup belongs to the sentence it closes: a sentence highlighted as a whole (`==…==`) or struck through (`~~…~~`) is selected, deleted and moved with its closing marks, as a closing quote or bracket always was. Whatever a shortcut does to the caret, the page follows it: a jump that would leave the caret off screen scrolls it back into view.

**Outlines** are nested checklists with a frame round them. Put `outline: true` in a document's frontmatter and every nested checklist in that file becomes one: a faint border on the document's own background, text a couple of pixels smaller than the prose and set in the app's UI font rather than the style's, completed items struck through and faded back, and the first unfinished item bold in the style's header colour. Hover an item and a grip appears beside its checkbox: drag it to move the item, children and all, with a marker showing where it will land — drag sideways to set how deep it lands. Dragged out past its parent, an item lands after that parent's branch, so the items it leaves behind keep their parent. ⌘] and ⌘[ indent and outdent an item the same way, children and all. A minimal footer carries **−** and **+** for the outline's text size (remembered on this device, for every outline) and two toggles — **hide completed items**, and **pin to bottom**, which lifts the outline out of the text and docks it to the bottom of the window or frame so it stays in view however far past it you write; drag the panel's top edge to set how much of the frame it takes. A pinned outline is worked on exactly as it is in the text — the panel is an editor of its own holding the outline's lines, so typing, the checkboxes, the grips, Option-↑/↓, ⌘[ / ⌘], formatting shortcuts and undo all behave the same there; the one thing it refuses is an edit that would stop a line being a checklist item, since that would split the outline and drop the rest of it out of the panel. In Zen Focus an outline folds away for the duration — a pinned one comes back as the one item you are on, at the top of the screen. Option-↑ / Option-↓ move an item among its siblings and take everything nested under it along. **Convert to Outline** in the command palette turns the list under the cursor into one: a checkbox on every item that hasn't got one, and the frontmatter switch set. **Convert to List** is the way back — it takes the boxes off the outline under the cursor, and drops the frontmatter switch when that was the document's last outline. **Outline mode** is the switch on its own, for a document whose checklists are already written. The same command in a notebook takes either of two selections: a flowchart folds into a single outline shape — the chart's tree read out as a nested checklist, in the order the chart was laid out — and a text shape that is a markdown list becomes an outline where it stands, checkboxes and frame and all. Nothing is stored but the markdown, so an outline is the same outline on either surface: drag one into a document and it arrives as the checklist it is. On a canvas it is worked on exactly as in a Doc — double-click it and you are typing into the rendered outline, with the same grips, Option-↑/↓, ⌘[ / ⌘], formatting, footer and undo; its checkboxes and footer answer without a double-click, and anywhere else a press picks the outline up like any other object. A pinned outline on a canvas docks to the bottom of the frame, centred, and its top edge drags to set its height, as a Doc's does.

**Ratchet Mode** is forward-only writing: pick a duration and the editor locks out deletion and navigation until the timer runs out. **Untimed**, above the durations, has no timer: the countdown's place holds an **End Ratchet Mode** button, and the session lasts until you press it. **Desk Ratchet** applies the same idea to a whole desk with no clock — committed text can be *rearranged* but never rewritten.

**Proofread** (grammar, via Harper) and **Spellcheck** modes underline issues inline with click-to-fix suggestions. Both run entirely on-device.

## Notebooks

Notebooks are infinite pan-and-zoom canvases for visual thinking: text shapes (with Markdown), images, freehand drawing with pressure-sensitive brushes, drag-area containers, layers, and bookmarks. Text shapes connect into **flowcharts** with directed arrows, which run beneath the text and fade out under any node they cross. A drag area joins a chart through its title — the node in its upper-left corner: point an arrow at the title, and dragging that node's parent brings the whole box and everything in it along. Any flowchart folds into an **outline** — one shape holding the whole tree as a nested checklist, with its own frame, checkboxes and footer; a **shelf** panel lists every shape as an outline; a **pocket** stashes shapes off to the side; **Brainstorm mode** captures rapid-fire ideas.

The wheel scrolls the canvas the way it scrolls a document, both ways; hold shift to pin a swipe to the axis you were already travelling on until you let go, and ⌘-wheel (or a trackpad pinch) to zoom. Locking a layer takes its contents out of reach of the pointer entirely — they still draw, they just stop being something you can pick up by accident. On iPad, only the Apple Pencil draws — fingers pan, pinch, tap to undo, and drag out a selection box without leaving the brush. Handwritten strokes can be **recognized into text** on-device (ML Kit on iPad; Apple Vision for images anywhere). Any selection can be **rasterized** into a single image that keeps tracking light/dark appearance. A drag area's **Copy** button puts everything written inside it on the clipboard as markdown, read left to right and top to bottom (nested boxes in their place; images and ink have no markdown to give). Text shapes set a `>` quote the way a Doc does — italic, a shade lighter, with a rule down its left.

**Splits** and **Grabs** open the canvas up. A split is a cut all the way across it — click with the Split tool and two dashed orange lines appear where you clicked (hold ⌘ to cut vertically instead). Drag the top line and everything above it moves; drag the bottom line and everything below follows, so you can push a page apart and write in the gap. Splits nest, images they cross are divided into masked halves that look untouched until you pull them apart, and text, strokes, groups and drag boxes are never cut in two — the whole grouping lands on one side. At rest the lines sit back as faint grey rules; hover one and it lights up with a padded band under your cursor, plus three actions — **collapse** (throw away what you wrote in the gap, close it back up, and fuse any image the split had cut back into one), **grab**, and **delete** (drop the lines, leave everything where it is). A **Grab** sweeps out a band, lifts everything inside it, closes the gap behind, and hands you a bar to place the lot somewhere else; ⌘Z after placing puts you back at the placing step.

**Bookmarks** work the same way in a notebook as in a PDF. The bookmark button in the toolbar lists them — click one to go to it, the pencil to rename or recolour it, × to delete it, ⌘-drag a row into a document for a link — and **Add Bookmark** at the foot of the list turns the pointer into a bookmark: click anywhere to drop one there. A bookmark is a coloured ribbon with its name beside it on a small chip, in the app's font at the same size however far you zoom. Drag it by the chip to move it, click the ribbon to change its colour (or copy its link, or delete it), click the name to rename it. They're listed in the shelf with their colours, and on a proofread notebook each one is also a small coloured dot on the page rail. A link to one — `[Name](hush-nb://…)`, from the list, the ribbon's Copy link, or ⌘-dragging the bookmark itself into a document — opens the notebook with the bookmark in the middle of the view — on a proofread notebook, the middle vertically only, so the column you've lined up sideways stays where it is (the same goes for the list and the shelf). Bookmarks travel with Splits and Grabs like the rest of the page, and undo with it. In a document, a link to a bookmark — a notebook's or a PDF's — shows that bookmark's ribbon, in its colour, just before the link text; recolour the bookmark and the icon follows. A notebook's colours are learned when it's opened on this device, and until then a link shows the colour the bookmark had when the link was made (an older link, or one to a deleted bookmark, gets a faded ribbon instead).

Notebooks export as `.hushnote` (lossless), PNG, JPG, or PDF.

## Cards

*Experimental.* A card is a short piece of markdown — a hundred words at most — that both Docs and notebooks show the same way: a small box, 300 pixels wide unless you resize it and as tall as its words plus a line, on the page's own background with a very light border, set in the app's font rather than the style's. Write one anywhere in a Doc by putting a line that is just `<<<` above the words and a line that is just `>>>` below them, or select some text and press **⌘⇧,**. On a canvas, **⌘-double-click** makes an empty card where you clicked, and ⌘⇧, turns the selected text shapes into cards.

Once it is a card it is out of the text: the caret steps over it, and its words are edited in the card itself, with all the markdown a Doc supports. Headings keep to the card's scale — a heading 1 four pixels larger than the text, a heading 2 two, the rest bold at the text's size — and their `#` marks show only while the card is being edited. The header — a grip and buttons for **colour**, **pin** (in a Doc), **insert at cursor** and **delete** — shows when the pointer is on the card; double-click the header to fold the card down to it, and again to open it. Insert at cursor puts the card's words back into the text at your caret (in a canvas, the last document you were typing in) and the card goes; while the pointer is on the button, a red arrow marks the spot. A card holds at most 100 words: at 100 nothing more goes in, and a card that arrives longer — pasted, or made from a longer selection — turns bright red and takes nothing more until it is shorter. Making a card of more than 50 words asks first.

**A card leaves a Doc only through its ✕** (or by being dragged or sent somewhere else). Backspace and Delete go round it: deleting on through a card joins the lines either side of it as if it weren't there, and the card moves up to sit beside the joined line. Deleting or typing over a selection that takes in a card removes the text around it and leaves the card where it was; undo still puts back or takes away a card along with whatever else it undoes.

**In a Doc a card never moves the text.** It sits in the right margin, level with the line after it, and stays beside that line as you write above it; cards that would overlap stack downward. Where the margin is narrower than 100 px — a narrow window, a document in a pane — the text gives up a 100 px gutter on its right for them. Drag a card by its header: over the text a line marks the line it will sit beside; let go in a margin and it stays where you put it. Drag its bottom-right corner to make it wider or narrower; as with a pane, the two edges meeting there light up while the pointer is on it. **Pin** a card to hold it where it is on screen while the text scrolls under it; unpin it and it stays where it now sits, beside the line it is level with, rather than going back to where it was pinned. Cards keep clear of whatever covers the edges of the editor — an inset sidebar, the right-hand bars, a docked pane, the right sidebar's toggle — narrowing to fit, and the gutter appears when that leaves too little margin. A card in the left margin moves with the text when the sidebar opens or closes.

**On a canvas a card is a text object**: click to select it, drag it, add it to a selection, group it, resize its width from the handles on its sides. Double-click it to edit its words.

A card can go anywhere: carry it off a canvas onto a document open in a pane, out of a Doc onto a canvas, or onto a document's or notebook's row in the sidebar (it lands at the end of the document, or in the middle of the notebook's current view) — it leaves where it was.

**The CARDS notebook** is a common home for cards, one per Inbox or project. Courier's Card sends to the Inbox's; dropping a card — from a Doc, a canvas or its sidebar row — on an **Inbox** or **project** row in the sidebar sends it to that one's; and **Send Cards to Inbox** in the command palette moves every card of the document or notebook in front of you to the Inbox's. It is made the first time a card is sent, and its cards line up in a grid that starts clear of the sidebar. In the sidebar it isn't listed like a file: it is pinned to the top of its Inbox or project, can't be dragged away, and shows only while it holds cards — folded it is just **Cards**, with the card icon, and clicking it opens the notebook; open, it is a bordered box of its cards. Either way its fold arrow sits under the container's icon and its card icons under the first letter of the container's name. The name CARDS is reserved for it — a file given that name becomes "CARDS (2)", and the notebook itself can't be renamed. With no cards left it drops out of sight until the next card is sent — unless you have put something else in it too (writing, a drawing, an image): then, when its last card goes, it moves to the top of the Inbox, named for the date and time ("2026-10-01 14.05"), so nothing of yours goes out of sight with it, and the next card sent there starts a new CARDS notebook.

Every document and notebook lists its cards in the sidebar as sub-rows, named by the first three words of the card's first line — folded away under the file until you open its twirl-down — which, unlike a folder's, shows only while the pointer is on the file or its cards (the CARDS notebook's too) — and listed above the file's pane icons, with each card's icon under the first letter of the file's name and the pane icons. On a canvas a card styles itself and has its own delete, so selecting one brings up none of the canvas's toolbar — no colour, text size, rasterize or delete. Click one to go to the card; drag one like a document, onto another file's row or out onto an editor or canvas. (A notebook's rows appear once it has been open on this device.)

In the file a card is just its markdown. Anything a card needs to remember — its colour, its width, whether it's folded, where it sits in a Doc's margin and whether it is pinned — rides a Hush comment on its last line:

```
<<<
Card ==content== here!
%%card {"xPos":820,"yPos":12,"bgColor":"#42a5f5"}%%
>>>
```

## Courier

Tap **Shift three times** — either Shift key, quickly, with nothing else pressed in between — and a sheet slides up from the bottom of the window, wherever you are: a document, a notebook, a PDF, Zen Focus. It leaves a quick note somewhere else without leaving what you're doing.

The left side chooses what to make. **Sticky** adds a second row — **Document**, **Desk** or **Global** — and a search over your documents or desks, on any desk; **Append** searches documents and adds the note as a new paragraph at the end of the one you pick; **Card** makes a card (see Cards) in a notebook called **CARDS** in the Inbox — made for you the first time — where successive cards line up in a grid. The right side is the thing itself, written in place: a sticky, in its paper colour, that you type straight into — or the last lines of the document, with the cursor waiting after them, where the note is written with the same markdown as anywhere else in the document — or the card itself. Switch between them and what you've typed comes with you.

Courier reopens where your last note went, so a second one to the same place is three taps, a sentence and ⌘↩. Escape or Cancel puts it away with the caret back where it was. It's also in the command palette, for when there's no keyboard.

## Timer

**Start timer** in the command palette opens a sheet in Courier's style: what (specifically) you're working on, **Timer** or **Alarm** — hours and minutes from now, or a time of day (the next time the clock reads it, today or tomorrow) — then one line of minutes that reads as a sentence: *5 min warmup, then 3 min breaks every 25 min. or No Breaks*. The **warmup** (0 to begin with) is a break at the very start of the session, before the work begins; **No Breaks** greys the break settings out — keeping their numbers for next time — and turns red while it's on. Under the settings, a timeline laid out from the current time draws the warmup (blue) and every break (a dash in the text colour) at their real length, with the time each starts written under it in grey — a time that would crowd the one beside it drops to a second row rather than being left out — and shows when you'll be done, redrawn as you change anything, with a one-line summary beneath it, and then Cancel and Start. Everything sits centred on the sheet. Start, and the timer sits at the bottom of the files sidebar, floating over the file list just above Add and Settings: the task, a thin progress bar under it, then the time to go, the time to the next break and the finish time, in whole minutes. Double-click the task to reword it; the clock carries on untouched. With the sidebar closed the timer shrinks to a small ring in the lower-left corner — as far from the left edge as from the bottom — that fills as the session runs: hover it for the minutes to the next break, click it to open the sidebar, drag it anywhere and it stays there. It fades with everything else in Focus mode. Breaks and the warmup are counted inside the session (an alarm still goes off when it was set to), the breaks falling every so many minutes from the end of the warmup; and both the bar and the ring have a small gap where each one falls; while a break runs the whole box turns red with white type, and a second bar, as thick as the first, fills left to right just under it (it's always there, invisible between breaks, so nothing shifts); the ring becomes a red disc with white bars and the seconds of break left in the middle. "Time for a break" arrives in red in the middle of the screen; a toast also says when time is up. During the warmup the bars and the ring's line are blue, the second bar fills with the warmup's own countdown, the ring shows the minutes of it left, and a toast says when it is over. For an alarm, the last ten minutes turn the minutes to go red, and the ring shows them without a hover. In the final minute of any session the ring counts the seconds down, 60 to 0. The ring's line turns red for the last five minutes of any session; when time is up it blinks five times and stays red, with a ✓ in the middle — click the ✓ to delete the timer.

There is one timer at a time, the same one on every desk and in every window, and it keeps counting while Hush is closed. **Delete timer** in the command palette takes it away — as does the **Done** button a finished timer shows in the sidebar; once a timer has finished, **Start timer** replaces it.

## Progress

**Show Desk Progress** in the command palette — and **Show Project Progress**, while the document you are in belongs to a project — opens a tally of the words you added each day. Two tabs: a **Calendar** of the month, each day's slot holding its count and tinted deeper the more you wrote, and a **Graph** of the same month as bars. Pick a day in either and the panel underneath breaks it down by document and, within each document, by section (the heading the words were written under). ‹ and › step through the months.

It counts words *added*, not the net change, so a morning spent rewriting a paragraph shows the new words you wrote rather than zero; a paragraph moved elsewhere adds nothing. Nothing is recorded for it: the counts are read back out of each document's version history, whether you wrote in the document on its own, in a pane, or in its project's joined editor — so it reaches back as far as your Versions do (every day is kept, one version a day once a week has passed).

## Clock

**Toggle clock** in the command palette floats a small analog clock over whatever you're working on: twelve short 1px marks, one every five minutes, and two 2px hands meeting at the centre, all in the text colour. No numbers. Its face is the window's background colour, so over a document it's just the marks and hands, and over a notebook or a PDF it's a solid disc. It floats over the document and any floating panes, and slides under the sidebars. Drag it anywhere; it stays on, and where you put it, across desks and relaunches.

Click a mark to set an alarm at that five-minute point. The mark grows to twice the length of the others and to the width of the hands, it and the minute hand turn the heading colour, and the rest of the clock fades back to 35%, so the two lines closing on each other are what you see; five minutes before the minute hand reaches it, every line on the clock turns red, and when it arrives the face flashes a few times — red lines on the page's colour, then a red disc with the lines in the page's colour, and back — before the clock goes back to normal. Click the same mark again to clear it. There is one alarm at a time — clicking another mark moves it.

## Organizing

- **Desks** are top-level workspaces, each with its own Inbox, Archive, and Trash, its own style, and its own last-open file. A desk can live *anywhere on disk* as a plain folder — see Sync below.
- **The Inbox** is where new files land, and its rows say so: each one carries the time it was last edited under its name, in red once it has been sitting there a week. A row's twirl-down sits level with the name, beside its icon.
- **Folders and projects** organize files. Dragging a file onto a closed folder or project drops it inside without opening it; hold it there for a second and it springs open, and it closes again if the drag moves on. Opening a file from anywhere — the sidebar, the command palette, Recent Files, YOU ARE HERE, a wikilink — unfolds the folders and projects above it in the sidebar, so you can always see where it lives; a project's documents concatenate into one continuous editor buffer with separators, so a long piece can live across many files. **Convert to Desk** in a folder's or project's menu makes it a desk of its own, contents and all, wherever it sat; **Move to Desk…** sends it whole to another desk. **Show numbers** in a project's menu numbers the documents that make up that text in the sidebar; notes, notebooks, stacks and the project's PDFs sit outside it and stay unnumbered. Projects convert to and from single tabbed documents, and a doc can be **split at its headings** into a project.
- **Stacks** lay out docs, notebooks, PDFs, and projects as side-by-side columns on one scrolling surface.
- **Desktops** show a project as a canvas of live file thumbnails you can arrange, pile, annotate, and connect — reading order drawn as arrows between the documents that make up the project's text (a doc used as a note sits outside it). A document's thumbnail sits on a pile of pages, one more for every 500 words; a notebook's shows its flowchart's arrows. Once a project's Desktop holds anything of yours — a note, a drawing, a pinned sticky — the Desktop button on the project's row in the sidebar stays in view, where hovering shows it, instead of appearing only on hover.
- **Floating panes** open any file as a reference window over your work: dock them to an edge (a docked document keeps the editor's column width, centred in the pane), pin them across documents, attach them to canvas positions, or embed them inline under a wikilink — the peek's **widen** button lets it fill the editor's width instead of the text column's, following the window as it resizes, and a notebook peeked this way opens with its toolbar folded to its grip. The keyboard follows the pointer: move it onto a pane and that pane takes what you type and scroll next, move it back onto the page and the document does — no clicking back and forth. A docked pane has its own right-hand sidebar: with one focused, `⌘⇧\` toggles its Overview (for a Doc) or its shelf (for a notebook or PDF) instead of the main document's. Panes float over the notebook toolbar and shelf and over the right-hand bars. A **Gutter** docks a notebook beside a document, scroll-locked to it, for marginalia.
- **Sticky notes** are small scoped reminders (per file, project, desk, or global) that float above everything and never appear in the file tree. They keep their paper colours whatever theme you're in, but switch to a dark-paper palette in a dark appearance so a bright sticky isn't the only thing glowing on the screen. A note shows in one window at a time: the window already displaying it keeps it, and a second window opened onto the same file or desk leaves it alone.
- **YOU ARE HERE** — type `YOUAREHERE` anywhere and the sidebar pins a red resume-reading row that jumps straight back to the marker. One per desk. The tag is set in the app's own font rather than the style's, and whatever follows it on its line — a note to yourself about what to do next — sits on a red tint in the same font, running straight on from the tag as one band. Text before the tag stays as it is. The note stays in the document: the sidebar row shows only the file's name.
- **Find** (`⌘F` in-document, `⌘⇧F` across the desk) with regex, whole-word, and replace — the in-document bar twirls open a replacement row with a Confirm button that rewrites every match in the document you're reading, and the desk-wide panel's replace covers every document it lists; **Versions** keeps automatic snapshots of every doc and notebook with a diff view and one-click restore, and notes under the list when the file was created; flags, color tints, multi-select batch actions, and a per-desk Recent Files list round out the sidebar. Selecting several files lists them in the editor area, where a handle on each row drags the batch into the order its actions use — the columns of a new stack, the documents of a new project, Combine's starting order, and **Copy to Clipboard**, which (for an all-document selection) copies every document's text in that order. The files themselves stay where they are.

## Research

- **Zotero**: connect your library, search references from the editor (`⌘⇧I` or type `[@` for inline citations), save PDFs into Hush, browse a paper's highlights in a drag-out pane — each with its own **Open in Zotero** link, which opens the PDF at that highlight — and insert page snapshots. Settings → Zotero has two downloads, each its own file and its own section: **References** and **Highlights** (every highlight in the library). With the highlights on this device the highlight browser opens a paper's highlights without asking Zotero (and needs no connection), its search list says how many each paper holds, and its ↻ still fetches a fresh copy. Either download can be stopped with its **Cancel** while it runs — as can the palette's Update Zotero References — and a cancelled download leaves the previous file as it was. Every library picker shows your collections as a folder tree beside the search results, so you can narrow to a folder instead of remembering a title. Search takes an author and a year the way you'd cite them — `Hoskins 2011`, `Hoskins, 2011` or `Hoskins (2011)` finds `@hoskins2011a` — since each word only has to match somewhere in the reference. ⌘-click a citation for Open in Zotero, or — while the PDF isn't in Hush yet — **Import PDF**, with three ways in under it: **download** it from Zotero, **paste** it from the clipboard (a PDF copied in the Finder, Preview or the Files app), or **import** a file you pick (each icon names itself on hover, or on a press-and-hold on iPad). The last two need no network: the PDF is filed as the linked Zotero entry, described from the library cache on this device. The pill stays a pill, and only a plain click opens its markdown for editing. A PDF row still waiting for its download offers the file and the clipboard in its sidebar menu too.
- **PDF viewer**: fast, annotation-aware (Zotero highlights and ink render on the pages), with an annotation shelf (drag its left edge to resize it; a row of colour swatches under its filter narrows the list to one highlight colour, as the highlight browser's column does), named colored **bookmarks** that work as deep links from your notes (the same bookmark list notebooks have — **Add Bookmark** at its foot arms a stamp, and the next click on a page drops a clip there), a **folded view** that collapses a paper to just its annotated regions, and a gallery **shelf** view of any PDFs folder with full-text-ish search over titles, bookmarks, and highlight text. A PDF carrying its annotations inside the file — one exported from Zotero, or marked up in Preview or Acrobat — lists them on the shelf after **Extract Annotations**: highlights with their text, underlines, notes, text boxes and drawings, each with its colour, comment and page (and, from Zotero, its tags), kept on this device and read back on every open. That is the way in for a PDF imported from disk or the clipboard, whose annotations Zotero's servers never sent; one already in the library's list is shown once. Double-click anywhere on a page for a **clip** — a bookmark that points at that exact spot, drawn as a dot with a dashed line out to a clip tab on the page's edge; ⌘-drag the dot to move it, and the line and tab follow.
- **Create Proofread Notebook** (command palette, or a PDF's row menu in the sidebar) turns a PDF into a `<name>-Proof` notebook. It asks which pages first — all of them by default, or `1-3, 5-8` — then renders each one at twice actual size on a blank background, stacked in one column, on a locked layer with a drawing layer over it. Whatever you had already highlighted or drawn on the PDF comes with it, printed into the pages, and its bookmarks and clips arrive as the proof's own bookmarks, where they were on the page. The highlighter arrives set to **blend**, so a mark over a page darkens the words rather than laying a slab over them — a checkbox in the brush flyout, on by default here and off in an ordinary notebook, where a dark canvas would swallow the ink. From there it's an ordinary notebook — ink, text, drag boxes, and especially Splits and Grabs, which is how you open space between paragraphs or move a section to where it belongs. A page rail rides the edge of the shelf: not a list of the pages the PDF had but a live minimap of the document as it stands, with your own strokes and notes sketched on top, so a split shows up there as two pieces, each the shape the cut left it. Click anywhere on it — a page or the gap between two — to glide down to it, without disturbing where you've scrolled to sideways. Drag its left edge to make it bigger, or hide it altogether from the toggle beside the canvas-rotation and background buttons. On iPad a weighted scroll wheel sits in the opposite corner, since the hardware has nothing that travels a long document well: drag its face to move through the document, flick it and it keeps spinning, touch it again to stop it dead. Its foot is a grip — drag it and the wheel moves, let go and it stays. Its cap is a magnifier: tap it and the same drag drives zoom instead of position, with the whole control outlined in red for as long as it does. Both wheel and rail travel with the proof into a floating pane or a stack column, where they measure against the pane's own edges rather than the screen's — so you can keep a proof open beside the draft you're writing from it.
- **Save to Desk** sits beside Export whenever the format is PDF, in both the document and notebook export modals: the rendered PDF lands in the desk's PDFs folder instead of on disk, ready to read, annotate, or proofread without a round trip through Finder.
- **Export**: documents and projects render to PDF through an embedded Typst pipeline (styles, line spacing, numbered headings, heading top margin, footnotes, tables with their columns, alignment and header row, and a real bibliography from your citations), plus Markdown, RTF, and one-shot Google Doc export. On iPad, Markdown leaves through the share sheet like PDF and RTF (Save to Files is one of its options); a document with images goes as a zip of the same `text.md` + `images/` folder the Mac writes. An image the export can't find prints as its markdown in red rather than taking the whole render down with it.

## Google Docs

Pasting from Google Docs converts rich formatting to Markdown automatically, and **Copy as Google Doc** round-trips the other way. Beyond that, individual documents can be **linked** to a Google Doc for explicit push/pull sync — non-destructive pushes preserve comments and suggestions on untouched text, Google Docs *tabs* map to `---Tab---` markers, and pulled **comments and suggested edits** appear inline with hover cards and Resolve/Accept/Reject actions.

## Sync

There is no sync service. Every desk is a self-contained folder of ordinary files (`.md`, `.hushnote`, `.hushstack`), and a desk can operate from **any folder on disk** — point Hush at an iCloud Drive, Dropbox, or Syncthing folder and let your provider move the bytes. **Use Local Folder as Desk** (`⌘P`, or the New Desk popup) is both halves of that: pick a plain folder and it becomes a desk with whatever was already inside it, or pick the folder your other device already keeps a desk in and you join that desk — same files, same history. A local desk is named by its folder, and both are yours to change afterwards: **Rename** a local desk and its folder is renamed with it, and **Move Local Folder…** puts the whole desk somewhere else. Neither reports success until every file in the old folder has turned up in the new one — a move that loses one is undone rather than announced. Outside changes fold back into the sidebar live; conflicted copies resolve automatically into version history; files a provider hasn't delivered yet are held, never dropped. A document edited on two devices at once — typically offline on one of them — is never silently overwritten: edits that don't overlap merge by themselves, and when they do overlap Hush asks whether to keep this device's version, the other one, or both side by side, with both already saved in Versions whichever you pick. **Local Folder** mounts give you the same direct-folder access without desk semantics, and archived desks zip into single shareable files. Automatic recovery snapshots protect synced desks, and **Backup App Data** zips everything.

## Everywhere you are

- **macOS**: menu-bar app, optional dock icon, always-on-top, fullscreen, hidden traffic lights.
- **iPad**: full app with Apple Pencil support, Files-app integration, real multi-window (Split View / Stage Manager), and touch-mode pills for keyboard-free use (command palette, a holdable ⌘, paste and undo), shown while Settings → Touch mode is on. On iPhone the palette pill is always there. A window that fills the screen hides the status bar (Settings → Hide status bar in full screen) and shows it again, window controls included, while the mouse is in the top-left corner — over the page, without pushing it down; a windowed one keeps it, since that's where iPadOS puts the window controls. iPhone gets a phone-tuned layout.
- **Multiple windows** on desktop and iPad — each window can sit on its own desk, and edits sync live between windows.
- **Keyboard-first**: every shortcut is rebindable in Settings, and **Show Shortcuts** displays a cheat sheet for whatever file type you're looking at.

```sh

```

## Development

```sh
npm run tauri dev
```

## Building

### macOS
```sh
npm run tauri build
```

### iOS

```sh
npm run ios:init
# Open xcode project and set up signing
npm run build:ios
```

The iOS deployment floor lives in one place — `bundle.iOS.minimumSystemVersion` in `src-tauri/tauri.conf.json` (currently 15.5, which is what ML Kit needs). Tauri maps it to `IPHONEOS_DEPLOYMENT_TARGET` when it generates the Xcode project, `ios:init` holds the Podfile to the same number, and the Xcode build phase passes it on to the Swift packages. **`src-tauri/gen/apple` is generated and gitignored, so changing the floor means re-running `npm run ios:init`** — `build:ios` alone won't regenerate it.

Xcode 27 also needs **swift-rs ≥ 1.0.8** (pinned in `src-tauri/Cargo.lock`). The three custom plugins' Swift packages are compiled by swift-rs, which up to 1.0.7 forced the iOS SDK on with `-Xswiftc -sdk`; Xcode 27's SwiftPM appends the host `-sdk`/`-target` *after* those, so the package built against the macOS sysroot with an iOS target and the whole thing collapsed on `UIKit`, `OpenGLES/EAGL.h` and `CoreServices/CSIdentityBase.h`. 1.0.8 passes `--triple` instead. Nothing in this repo can work around it — don't downgrade that lock entry.

## Data

Files and settings are stored in:
- **macOS**: `~/Library/Application Support/com.hush.app/`
- **Linux**: `$XDG_DATA_HOME/com.hush.app/`

Every desk is a folder of plain files inside that directory (or wherever you pointed a local desk), so your writing is never locked in.
